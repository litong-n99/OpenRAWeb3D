## 1. 总标准

### 1.1 文件格式

- **交付格式**: `.glb` (glTF 2.0 Binary)，所有纹理和数据内嵌在一个文件中
- **不支持**: .vxl、.hva 等体素格式。这些是 OpenRA 桌面版的旧格式，不再使用
- **一个模型一个文件**：每个单位/建筑一个独立的 `.glb` 文件
- **文件名**：使用 OpenRA 的 Actor ID（如 `1tnk.glb`、`harv.glb`、`e1.glb`），大小写敏感，与 OpenRA YAML 定义保持一致

### 1.2 坐标系统

| 轴 | Blender | Babylon.js | 含义 |
|----|---------|-----------|------|
| X | +X | +X | 前方/东方（模型正面朝向） |
| Y | +Y | +Y | 上方/高度 |
| Z | +Z | +Z | 右方/南方 |

**关键要求**：
- Blender 默认的 **+Y-up** 坐标系与 Babylon.js 完全一致，导出时选择 **+Y Up**
- 模型的 **前方（Forward）必须是 +X 方向**。在 Blender 中建模时，确保单位/建筑的正面对着 +X 轴
- 运行时，引擎通过 body rotation 来处理朝向问题，建模师只需保证模型自身的 +X 方向为"前方"

### 1.3 缩放规则

- **Blender 建模比例**: 1 Blender 单位 = 1 米（真实世界比例建模）
- **游戏世界单位**: 1 世界单位（WDist）= 1/1024 米
- **默认渲染缩放**: 12 倍（引擎在运行时应用）
- **换算关系**:
  - 1 格（Cell）= 1024 世界单位 = 1 米
  - scale 12 时，1 格 = 12 Babylon.js 米

**尺寸参考表**：

| 类别 | 格数（Cells） | 世界单位 | Blender 单位（米） | 渲染尺寸（scale 12） |
|------|:-----------:|:--------:|:----------------:|:-------------------:|
| 步兵 | 1 | 1024 | ~1.8 米高 | ~21.6 米高 |
| 小型车辆（矿车、APC） | 1.5-2 | 1536-2048 | ~1.5-2 米 | ~18-24 米 |
| 中型坦克 | 2-3 | 2048-3072 | ~2-3 米 | ~24-36 米 |
| 重型坦克（猛犸） | 3-4 | 3072-4096 | ~3-4 米 | ~36-48 米 |
| 小型建筑（发电厂、兵营） | 2x2 - 2x3 | 2048x2048 - 2048x3072 | ~2x2 - 2x3 米 | ~24x24 - 24x36 米 |
| 中型建筑（工厂、雷达） | 3x3 - 3x4 | 3072x3072 - 3072x4096 | ~3x3 - 3x4 米 | ~36x36 - 36x48 米 |
| 大型建筑（超武） | 3x3 - 4x4 | 3072-4096 | ~3-4 米 | ~36-48 米 |
| 超大型建筑 | 4x4 - 6x4 | 4096-6144 | ~4-6 米 | ~48-72 米 |
| 舰船（驱逐舰） | 3-4 | 3072-4096 | ~3-4 米 | ~36-48 米 |
| 舰船（巡洋舰） | 4-5 | 4096-5120 | ~4-5 米 | ~48-60 米 |
| 飞机/直升机 | 2-3 | 2048-3072 | ~2-3 米 | ~24-36 米 |

**建筑尺寸映射规则**：
- 每个 cell 格 = 1 Blender 米
- 建筑宽度 = Footprint Dimensions X × 1m，深度 = Footprint Dimensions Y × 1m
- 对于含 `==`（dock / 生产出口）的行，模型应在对应侧延伸出 dock 区域（约 0.5-1m）
- 对于含 `_`（可通行）的行，模型在该位置留空
- 不规则建筑（如 PROC 矿厂）的模型应为 L 形或对应形状，不可简单地做成正方体

**注意**：引擎会在导入时自动应用 12 倍缩放。建模师在 Blender 中按照真实世界比例（1 米级）建模即可，不需要在模型层面做任何缩放。

### 1.4 PBR 材质标准

OpenRAWeb3D 使用 PBR (Physically Based Rendering) 材质系统。由于原版 OpenRA 使用 256 色调色板的低模风格，材质设置应符合 C&C 系列的美术风格。

#### 材质参数

| 参数 | 值 | 说明 |
|------|----|-----|
| **metallic** | `0.0`（非金属） | 军事载具为磨砂涂装，非金属材质 |
| **roughness** | `0.5 - 0.8` | C&C 美术风格不反光。车辆 0.5-0.6，建筑 0.7-0.8 |
| **alphaMode** | `OPAQUE`（默认） | 绝大多数模型不透明。特殊模型见清单标注 |

#### 纹理规范

- **推荐分辨率**: 512x512 或 1024x1024（以保持与原版 256 色调色板风格一致）
- **纹理类型**: Base Color（基础色）+ 可选 Normal（法线贴图）+ 可选 Metallic/Roughness（金属度/粗糙度）
- **格式**: PNG（内嵌在 .glb 中）
- **UV 映射**: 所有可见面必须有 UV 展开，不可有重叠（如有需要可放在 UV 0-1 范围外）
- **纹理不需要手绘复杂细节**，建议使用纯色块面 + 简单阴影的风格，与原版 C&C 低模风格保持一致

#### 阵营色部件 (Player Color)

- 需要引擎运行时替换颜色的部件（如阵营标识、涂装条纹）必须使用专用的 material slot
- **material slot 名称**: `player_color`
- 该 material 的基础色（Base Color）可使用**中性灰色（RGB 128, 128, 128）**作为占位，引擎运行时通过 ShaderMaterial uniform 替换
- 阵营色部件应为模型中**独立的网格体/面**，不可与不可替换的 base color 部件混合在同一 material 中

#### 光照参考值（引擎默认）

建模时可在 Blender 中设置以下参考光照来预览效果：

- **光源仰角**: 50 度（从水平面上方）
- **光源方向角**: 240 度
- **环境光**: RGB [0.6, 0.6, 0.6]
- **漫反射光**: RGB [0.4, 0.4, 0.4]

> 注意：Blender 中的光照预览仅供参考，最终效果由 Babylon.js 引擎中的光照配置决定。

### 1.5 节点层级和命名规范

模型必须使用以下节点层级结构。引擎代码通过节点名称查找 turret 和 barrel 来控制动画和旋转。

#### 基本结构

```
body（根节点）
├── turret（炮塔，子节点）
│   └── barrel（炮管，孙节点）
└── ...其他肢体/部件
```

#### 节点命名规范

| glTF 节点名 | 用途 | 必须存在 | 说明 |
|------------|------|:-------:|------|
| `body` | 根节点/车身 | 是 | 所有模型都必须有。包含主体网格、基础动画 |
| `turret` | 炮塔/旋转部件 | 条件 | 有炮塔的单位（坦克、炮台等）。在 `body` 之下，可以水平旋转 |
| `barrel` | 炮管/仰角部件 | 条件 | 有独立炮管的单位（需先有 `turret`）。在 `turret` 之下，可以俯仰 |

#### 节点层级规则

1. **只有 `body` 的单位**：步兵、无炮塔车辆（APC、矿车、MCV 展开前）、建筑、船只（不需要炮塔动画的）
2. **`body` + `turret` 的单位**：大部分主战坦克、炮台、防空炮
3. **`body` + `turret` + `barrel` 的单位**：有独立炮管动画的坦克（如猛犸坦克、驱逐舰炮座、特斯拉线圈、自行火炮的炮管仰角）

> 每个单位的准确节点结构见 [模型清单](#2-模型清单与规格) 的"节点结构"列。

#### 网格体（Mesh）命名建议

- 主体网格：`body_mesh`、`chassis_mesh`、`hull_mesh`
- 炮塔网格：`turret_mesh`
- 炮管网格：`barrel_mesh`
- 车轮/履带：`wheel_LF`、`wheel_RF`、`track_L`、`track_R`
- 阵营色网格：`player_color_body`、`player_color_turret` 等

> 引擎主要通过 Empty/Transform 节点名（`body`/`turret`/`barrel`）来定位，网格名仅供参考。但保持规范命名有助于团队协作。

#### 模型原点

- `body` 的原点应在模型底部中心（与地面接触点），Y=0 为地面
- `turret` 的原点应在炮塔的实际旋转中心（通常是炮塔底座的几何中心）
- `barrel` 的原点应在炮管的俯仰旋转轴上

### 1.6 动画规范

#### 帧率

- **帧率**: 25 fps（匹配 OpenRA 40ms tick）
- **关键帧插值**: Linear（线性）

#### Animation Clip 命名

每个 animation clip 必须是独立的 glTF animation，使用以下名称：

| Clip 名称 | 用途 | 适用对象 | 说明 |
|----------|------|---------|------|
| `idle` | 默认待机动画 | 所有模型 | **必须有**。如车身微动、呼吸效果、旗帜飘动等。可以是非常微妙的动画甚至单帧静态 |
| `run` | 移动动画 | 移动单位 | 车轮/履带转动、步兵行走、舰船/飞机航行。建筑不需要。建模师应在 `run` clip 中制作车轮旋转动画（glTF 动画擅长处理循环旋转），引擎在移动时播放 |
| `turret` | 炮塔初始姿态 | 有 turret 的模型 | 炮塔的 **rest pose**（初始姿态）。引擎代码会在此基础上程序化旋转炮塔，此 clip 可为单帧姿态 |
| `barrel` | 炮管初始姿态 | 有 barrel 的模型 | 炮管的 **rest pose**（初始姿态）。引擎代码会在此基础上程序化俯仰炮管，此 clip 可为单帧姿态 |
| `death` | 死亡动画 | 所有模型 | **可选但强烈推荐**。步兵倒地、车辆起火变形/爆炸前崩塌、建筑塌毁。引擎通过 `WithDeathAnimation` trait 触发播放 |
| `make` | 建造动画 | 建筑 | **可选但强烈推荐**。建筑物从地面展开/升起的过程（从无到有）。引擎通过 `WithMakeAnimation` trait 在建造完成时触发 |

> **重要**：动画 clip 名必须与上述完全一致（小写英文），引擎代码会按名称查找对应的 animation clip。

#### 动画规则

1. **`idle` 必须存在**：所有模型都必须有一个 `idle` animation clip，即使是单帧静态 pose
2. **动画循环**：`idle` 和 `run` 应为无缝循环动画
3. **不要烘焙骨骼动画到顶点**：保持骨骼/节点变换动画，不要 bake 到 vertex
4. **动画长度**：`idle` 建议 0.5-2 秒，`run` 建议与步态周期匹配（通常 0.5-1 秒）
5. **turret/barrel 动画**：建模师只需制作 rest pose（第 0 帧默认姿态），炮塔旋转和炮管俯仰由引擎在运行时程序化处理（见 [1.8 动画职责边界](#18-动画职责边界)）
6. **动画帧范围**：从第 0 帧开始，不要有负帧偏移
7. **death 动画**：一次性播放（不循环），建议 0.5-2 秒。步兵建议制作倒地动画；车辆可包含爆炸前变形（引擎会叠加爆炸粒子特效）
8. **make 动画**：一次性播放（不循环），建筑从地面升起/展开。建议 1-3 秒

### 1.7 导出设置（Blender glTF 导出器）

使用 Blender 内置的 glTF 2.0 导出器（**不要使用第三方插件**）。路径：File -> Export -> glTF 2.0 (.glb/.gltf)

| 设置项 | 推荐值 | 说明 |
|--------|--------|-----|
| **Format** | `glTF Binary (.glb)` | 必须 |
| **Y+ Up** | `true`（勾选） | 与 Babylon.js 一致 |
| **Transform** | 不勾选 +Y Up（使用默认） | Blender 默认就是 +Y Up，通常不需要额外勾选 |
| **Include** > Selected Objects | 按需 | 确保只导出需要的模型 |
| **Include** > Visible Objects | 按需 | 同上 |
| **Include** > Custom Properties | 可选 | 如使用了自定义属性可勾选 |
| **Include** > Cameras | `false` | 不导出 Blender 相机 |
| **Include** > Punctual Lights | `false` | 不导出 Blender 灯光（引擎有自己的光照） |
| **Data** > Mesh | 勾选 `Apply Modifiers` | 导出前应用所有修改器 |
| **Data** > Mesh | 不勾选 `UVs` 之外的高阶属性 | 按需即可 |
| **Data** > Material | `Export` | 导出 PBR 材质 |
| **Data** > Material | 选择 `glTF PBR` 导出方式 | 不要 bake 到纹理 |
| **Data** > Shape Keys | 如果使用了形态键则勾选 | 一般不需要 |
| **Data** > Skinning | 如果使用了骨骼动画则勾选 | 一般不需要 |
| **Animation** > Animations | `true`（勾选） | 导出所有 animation clips |
| **Animation** > Animation Mode | `Actions` | 每个 Action 导出为一个独立的 animation clip |
| **Animation** > Shape Keys Animation | 按需 | 一般不需要 |
| **Animation** > Bake All Objects | `false` | 不要烘焙，保持原始节点变换 |
| **Animation** > Sampling Rate | `25` fps | 与其他设置保持一致（可选，推荐选 25fps 或使用默认场景帧率） |
| **Compression** | 不勾选 | 不压缩，保持质量 |

#### Action 命名和导出

1. 在 Blender 中为每个动画创建独立的 **Action**
2. Action 名称必须与目标 clip 名称**完全一致**：`idle`、`run`、`turret`、`barrel`、`death`、`make`
3. 导出时确保所有 Action 都被包含
4. 每个 Action 的帧范围应该从第 0 帧开始

### 1.8 动画职责边界

本节明确哪些动画由**建模师制作**（glTF animation clips），哪些由**引擎运行时程序化处理**。这是建模师与程序员之间的关键接口。

#### 建模师负责（glTF animation clips）

| Clip | 说明 | 适用对象 |
|------|------|---------|
| `idle` | 待机微动：呼吸、车身微震、旗帜飘动 | 所有模型 |
| `run` | 移动循环：步兵行走、车轮/履带转动、舰船航行。**建议在 clip 中制作车轮旋转动画**，引擎在移动时播放此 clip | 所有移动单位 |
| `turret` | 炮塔的**初始姿态**（rest pose）。引擎代码会在此基础上程序化旋转炮塔 | 有 turret 节点的模型 |
| `barrel` | 炮管的**初始姿态**（rest pose）。引擎代码会在此基础上程序化俯仰炮管 | 有 barrel 节点的模型 |
| `death` | 死亡动画：步兵倒地、车辆爆炸前变形、建筑坍塌。引擎通过 `WithDeathAnimation` trait 触发播放 | 所有模型（推荐） |
| `make` | 建造动画：建筑物从无到有的展开/升起过程。引擎通过 `WithMakeAnimation` trait 在建造完成时触发 | 建筑（推荐） |

#### 引擎负责（程序化运行时处理）

以下变换和特效由引擎在运行时根据游戏逻辑动态计算，**建模师不需要在模型中制作这些动画**：

| 引擎职责 | 对应 Trait | 说明 |
|---------|-----------|------|
| **炮塔旋转** | `Turreted` | 根据目标方向实时旋转 `turret` 节点 |
| **炮管俯仰** | `AttackTurreted` / `WithSpriteBarrel` | 根据目标距离/高度实时调整 `barrel` 节点俯仰角 |
| **单位朝向** | `BodyOrientation` | 根据移动方向旋转整个 `body` 节点 |
| **攻击特效** | `WithAttackAnimation` / `WithAttackOverlay` | 枪口火焰、激光束等叠加特效，使用独立的 effects 系统 |
| **建造过程特效** | `WithMakeOverlay` | 建造中的脚手架/闪光效果叠加 |
| **放置动画** | `WithBuildingPlacedAnimation` | 建筑物放置到地图时的落地/展开动画 |
| **采集动画** | `WithHarvestAnimation` | 矿车采矿时的采集交互动画 |
| **维修/治疗特效** | `WithRepairOverlay` | 修理火花/医疗特效叠加 |
| **伤害叠层** | `WithDamageOverlay` | 根据血量改变模型外观（冒烟、起火） |
| **隐形/迷彩** | `Cloak` | 控制模型透明度和视觉效果 |
| **经验升级** | （引擎内置） | 经验提升/晋升视觉效果 |
| **颗粒/烟雾/火焰** | `FloatingSpriteEmitter` | 粒子系统——烟雾、火焰、火花等 |
| **建造门动画** | `WithProductionDoorOverlay` | 工厂生产出口门的开合 |

#### 关键规则

1. **建模师只需做视觉上完整的动画**：`idle`、`run`、`death`、`make`（建筑），`turret`/`barrel` 只需 rest pose
2. **任何涉及运行时计算的变换**（根据目标旋转、根据血量变化、根据距离俯仰）都由引擎处理，建模师不需要在模型层面实现
3. **触发性特效**（爆炸、枪火、电弧、烟雾）由引擎的 effects 系统叠加，建模师不需要在模型中实现
4. **车轮/履带旋转**：建议建模师在 `run` clip 中制作车轮旋转动画（glTF 动画很擅长处理循环旋转），引擎在移动时播放 `run` clip
5. **death 和 make 是一次性播放的 clip**（不循环），引擎通过对应的 trait 在适当时机触发
6. **如有疑问**：优先咨询项目架构师，确定某个动画效果是由建模还是引擎实现

## 2. 模型清单与规格

以下清单覆盖 OpenRA 四个主要 Mod：Red Alert (RA)、Tiberian Dawn (TD)、Dune 2000 (D2K)、Tiberian Sun (TS)。

**图例**：
- **节点结构**：B = body only, B+T = body+turret, B+T+B = body+turret+barrel

### 3.2 导前检查清单

在导出 .glb 文件之前，完成以下检查：

- [ ] **模型方向**：模型正面对 +X 轴
- [ ] **模型原点**：body 原点在底部（Y=0 地面层），turret/barrel 原点在旋转轴
- [ ] **节点命名**：Empty/Transform 节点命名为 `body`、`turret`、`barrel`（大小写严格一致）
- [ ] **节点层级**：`body` 为根，`turret` 在 `body` 之下，`barrel` 在 `turret` 之下
- [ ] **材质名称**：阵营色 material 命名为 `player_color`
- [ ] **材质参数**：metallic=0, roughness 0.5-0.8, alphaMode=OPAQUE
- [ ] **纹理分辨率**：512x512 或 1024x1024，内嵌 PNG 格式
- [ ] **UV 展开**：所有面有 UV，无重叠（非 player_color 部件）
- [ ] **Animation 数量**：有 idle clip，其他按需要（run/turret/barrel/death/make）
- [ ] **Action 命名**：idle/run/turret/barrel/death/make，与规范一致
- [ ] **帧率**：25fps（场景帧率设置）
- [ ] **网格清理**：应用所有修改器，删除多余的材质 slot 和未使用的网格
- [ ] **原点重置**：没有孤立的 transform 残留
- [ ] **删除冗余对象**：删除未使用的空物体、辅助线、灯光、相机
- [ ] **法线方向**：所有面的法线朝外，使用 `Recalculate Outside`
- [ ] **三角面化**：对于硬表面模型，建议在导出前三角化（Triangulate modifier），确保引擎渲染一致
- [ ] **面数检查**：控制在全模型 500-2000 三角面之间，建筑最多 5000 面

### 3.3 文件命名约定


## 4. 质量检查标准

### 4.1 面数限制（低模风格）

OpenRAWeb3D 延续 C&C 系列的低模美术风格。面数过多会破坏风格一致性并降低性能。

| 模型类别 | 三角面数上限 | 推荐范围 |
|---------|:----------:|:------:|
| 步兵 | 500 | 200-400 |
| 小型车辆 | 1000 | 500-800 |
| 中型坦克 | 1500 | 800-1200 |
| 重型/超重型坦克 | 2000 | 1200-1800 |
| 飞机/直升机 | 1500 | 800-1300 |
| 舰船（小型） | 1500 | 800-1200 |
| 舰船（大型） | 2500 | 1500-2200 |
| 建筑（小型，1x1-2x2） | 1500 | 800-1200 |
| 建筑（中型，3x3） | 3000 | 1500-2500 |
| 建筑（大型，4x4+） | 5000 | 2500-4000 |
| 防御塔 | 1000 | 500-800 |
| 树木/环境装饰 | 200 | 50-150 |

**面数优化技巧**：
- 对圆柱体使用 6-8 边而不是 16-32 边
- 使用纹理贴图代替过多几何细节
- 隐藏面（底部、内部）可以删除
- 优先使用简单的 box 和 cylinder 体块构建
- 小尺寸零件（把手、天线等）可以用单面片

### 4.2 纹理要求

| 项目 | 要求 |
|------|------|
| **分辨率** | 512x512（推荐）或 1024x1024（最大） |
| **格式** | PNG，内嵌在 .glb 中 |
| **颜色空间** | sRGB |
| **Alpha 通道** | OPAQUE 模型不需要 alpha。如需透明（如窗户玻璃），alpha 通道必须精确 |
| **风格** | 纯色块面 + 简单阴影，不要照片级纹理 |
| **UV 布局** | 无重叠 UV（player_color 部件之外） |
| **玩家色区域** | 使用独立的 `player_color` material slot，纹理中该区域为中性灰色 |
| **纹理数量** | 尽量只使用一张 Base Color 贴图。可选 Normal 贴图添加低模细节 |

### 4.3 动画验证步骤

导出 .glb 后，使用以下步骤验证动画：

1. **Blender 中预览**：在 Action Editor 中切换 Action，确认每个动画正确播放
2. **外部查看器验证**：将 .glb 拖入 [glTF Viewer](https://gltf-viewer.donmccurdy.com/) 或 Babylon.js Sandbox，检查：
   - 模型外观是否正确（PBR 材质、纹理 UV）
   - 节点层级是否保留（body -> turret -> barrel）
   - 所有 animation clips 是否正确显示在动画列表中
   - 播放每个 clip，检查动画是否正确，有无错位
3. **循环检查**：`idle` 和 `run` 动画的首尾帧是否无缝衔接
4. **方向验证**：
   - 模型正面是否朝向 +X（在 glTF Viewer 中检查默认视角）
   - turret 的旋转是否正确（绕 Y 轴）
   - barrel 的俯仰是否正确（绕 Z 或 X 轴，取决于模型朝向）
5. **阵营色验证**：`player_color` material slot 是否正确导出为一个独立的 material

### 4.4 常见问题排查

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 模型在 Babylon.js 中方向错误 | Blender 导出时方向不对 | 确保模型正面为 +X，导出时不要勾选 +Y Up（Blender 默认已是） |
| 动画不播放 | Animation clip 名称不匹配 | 检查 Action 名是否与规范一致（idle/run/turret/barrel/death/make，小写） |
| Turret 不旋转 | 节点命名错误或层级不对 | 检查 glTF 输出中是否有名为 `turret` 的节点作为 `body` 的子节点 |
| 材质太亮/太暗 | PBR 参数不正确 | 确保 metallic=0，roughness 在 0.5-0.8 之间 |
| 阵营色不替换 | Material slot 名称不对 | 确保使用了名为 `player_color` 的 material |
| 面数过高 | 使用了过多几何细节 | 参考面数限制表，简化模型 |
| 纹理不显示 | UV 未导出或纹理未内嵌 | 检查 UV 是否展开，导出时选择 glTF Binary 格式 |
| 模型在引擎中太大/太小 | 建模比例不匹配 | 确保使用真实世界比例（1 Blender 单位 = 1 米），引擎自动缩放 |

## 附录 A：Blender 工作流程建议

### A.1 推荐工作流程

1. **新建项目**：设置单位为米（Metric），帧率 25fps
2. **参考图像**：导入原版 OpenRA 的渲染图或 TS mod 的体素渲染图作为背景参考
3. **构建基本体块**：用 box/cylinder 构建粗模（block-in），确定比例和外形
4. **细化几何**：添加细节，但保持面数在限制内
5. **UV 展开**：展开 UV，分配材质
6. **创建节点层级**：按规范添加 Empty 节点（body/turret/barrel）
7. **绑定网格到节点**：将网格体设为对应节点的子对象
8. **制作动画**：为每个 Action 设置关键帧
   - 所有模型：`idle`（必须）
   - 移动单位：`run`
   - 有炮塔/炮管：`turret`/`barrel`（仅 rest pose）
   - 推荐：`death`（所有模型）、`make`（建筑）
9. **导出检查**：按导前检查清单逐项确认
10. **导出 .glb**：使用推荐设置导出
11. **外部验证**：在 glTF Viewer 中验证

### A.2 参考站点

- **glTF 规范**: https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html
- **glTF 在线查看器**: https://gltf-viewer.donmccurdy.com/
- **Babylon.js Sandbox**: https://sandbox.babylonjs.com/
- **Blender glTF 导出器文档**: https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html
- **OpenRA 项目**: https://github.com/OpenRA/OpenRA
- **OpenRA 资源站**: https://resource.openra.net/ (查看单位外观参考)

### A.3 .blend 文件管理

- **命名**: `{actor_id}.blend`
- **目录**: `assets/models/{mod}/{actor_id}.blend`
  - 例如: `assets/models/ra/1tnk.blend`
- **版本控制**: 将 `.blend` 文件纳入 Git LFS 或单独存储。`.glb` 文件放在 `public/models/{mod}/` 下
- **备份**: 定期备份 `.blend` 源文件，不要只保留导出的 `.glb`

## 附录 B：节点结构示意图

### B.1 body only（步兵、无炮塔车辆、建筑）

```
Scene (World Origin)
└── body (Empty/Transform, Y=0 为地面)
    ├── body_mesh (步兵身体/车身/建筑主体)
    ├── wheel_mesh (车轮，如果有)
    └── accessory (附件)
```

### B.2 body + turret（有炮塔无独立炮管）

```
Scene (World Origin)
└── body (Empty/Transform, Y=0 为地面)
    ├── body_mesh (车身)
    ├── turret (Empty, 原点=炮塔旋转中心)
    │   └── turret_mesh (炮塔整体，含炮管)
    ├── wheel_LF (左前轮)
    └── wheel_RF (右前轮)
```

### B.3 body + turret + barrel（有独立炮管）

```
Scene (World Origin)
└── body (Empty/Transform, Y=0 为地面)
    ├── body_mesh (车身)
    ├── turret (Empty, 原点=炮塔旋转中心)
    │   ├── turret_mesh (炮塔底座)
    │   └── barrel (Empty, 原点=炮管俯仰轴)
    │       └── barrel_mesh (炮管)
    ├── track_L (左履带)
    └── track_R (右履带)
```

### B.4 双炮管结构（猛犸坦克等）

```
Scene (World Origin)
└── body (Empty/Transform)
    ├── body_mesh
    ├── turret (炮塔旋转)
    │   ├── turret_mesh
    │   ├── barrel_left (左炮管俯仰轴)
    │   │   └── barrel_mesh_left
    │   └── barrel_right (右炮管俯仰轴)
    │       └── barrel_mesh_right
    └── ...
```

> 对于双炮管的单位，请与程序团队确认引擎如何索引多个 barrel 节点。当前引擎支持 `barrel` 节点（单数），多炮管可能需要命名为 `barrel_left`/`barrel_right` 或使用数字后缀。
