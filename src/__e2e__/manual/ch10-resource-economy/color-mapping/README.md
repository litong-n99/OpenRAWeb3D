# ResourceRenderer - 资源类型颜色与变体序列对比

> **人工验收测试页**
> 模块: ResourceRenderer (资源精灵颜色映射)
> 测试ID: `resource/color-mapping`
> OpenRA 对照: `ResourceRendererInfo.resourceTypes` — palette/image/sequences/name 配置字段
> 创建日期: 2026-06-14

---

## 测试目标

本测试页面验证不同资源类型使用正确的颜色和精灵序列进行渲染。在 OpenRA 中，每种资源类型在 `ResourceRendererInfo.resourceTypes` 中定义 image（序列图）、sequences（变体名列表）、palette（调色板名）和 name（工具提示名）。

自动化单元测试可以验证配置解析的 JSON 正确性、`_chooseVariant()` 的哈希分布，但以下关键行为必须由人工肉眼判断：

1. **颜色正确性**：Tiberium 应渲染为绿色系，Ore 为金色系，Spice 为橙红系，Gems 为紫色系。
2. **变体区分度**：同一资源类型的不同变体应在颜色上有肉眼可分辨的差异（色相偏移 10-20 度）。
3. **密度渐变平滑**：从密度 1 到密度 maxDensity，颜色过渡应无跳跃、无逆序。
4. **类型间不混淆**：四种资源类型的颜色范围应互不重叠，视觉上易于区分。

## B. 期望结果（可量化验收标准）

### 期望 1: 资源类型颜色精确映射

**操作**: 默认「网格」布局，观察四个资源类型面板。

**量化标准**:
| 资源类型 | 密度=1 预期颜色 (hex) | 密度=max 预期颜色 (hex) | 容差 |
|---------|----------------------|------------------------|------|
| Tiberium | #0D4014 (深绿) | #00CC44 (亮绿) | ΔE < 20 或肉眼一致 |
| Ore | #331F05 (深棕金) | #DAA520 (金色) | ΔE < 20 |
| Spice | #2E1402 (深红) | #CC5500 (橙红) | ΔE < 20 |
| Gems | #260526 (深紫) | #CC44CC (紫红) | ΔE < 20 |

**验证方法**: 查看每块面板左端（低密度）和右端（高密度）颜色，与预期 hex 值对比（可 focus 颜色图例面板查看精确 hex 值）。

**失败判定**: 若 Tiberium 呈现红色或蓝色 → 颜色配置错误（BLOCKER）。若颜色图例中的 hex 值与预期偏差 > 30（ΔE）→ 调色板映射错误（MAJOR）。

### 期望 2: 变体间可分辨色彩差异

**操作**: 观察每个资源类型面板中的不同行（每行一个变体），确认同一列（相同密度）下不同行的颜色有差异。

**量化标准**:
| 检查项 | 预期 |
|--------|------|
| 同密度同类型不同变体 | 肉眼可辨颜色差异（色相偏移 >= 5 度） |
| 变体偏移方向一致 | 所有变体在色相环上偏移方向一致（如 V1 偏绿、V2 偏蓝） |
| 4 变体类型 (Tiberium/Ore/Gems) | 4 行颜色均可区分 |
| 3 变体类型 (Spice) | 3 行颜色均可区分 |
| 点击「比较调色板 (原色 vs 偏移)」 | 同面板所有行颜色变为相同 → 确认变体偏移被移除 |

**失败判定**: 若某类型的所有变体颜色肉眼无法区分 → 变体偏移量不足（MAJOR）。若变体颜色与基础色相差超过 40 度色相 → 变体偏移过大（MINOR）。

### 期望 3: 密度渐变无跳动无逆序

**操作**: 观察每个面板从左到右的颜色变化。

**量化标准**:
| 检查项 | 预期 |
|--------|------|
| 颜色明度趋势 | 从左到右单调递增（越来越亮） |
| 颜色饱和度趋势 | 从左到右单调递增（越来越鲜艳） |
| 跳变检查 | 相邻密度级别之间颜色差异 < 15%（无突兀跳变） |
| 逆序检查 | 右端密度必须比左端亮（100% 不能出现右侧暗于左侧） |
| 均匀性 | 每步颜色差异大致相等（肉眼） |

**验证方法**: 逐列扫视每个面板，确认颜色从左到右平滑提亮。悬停不同列确认 hex 值递增。

**失败判定**: 若某密度级别颜色突然变暗（逆序）→ lerp 算法错误（BLOCKER）。若密度间有可见跳变 → lerp 步数不足（MAJOR）。

### 期望 4: 布局切换正确重新排列

**操作**: 切换布局模式为「并排 (Side-by-side)」→ 观察 → 切换为「密度色轮」。

**量化标准**:
| 布局模式 | 视觉效果 |
|---------|---------|
| 网格 | 4 个矩形面板，每面板行=变体数、列=密度级别 |
| 并排 | 面板排列为 2×2，间距均匀，无重叠 |
| 密度色轮 | 4 个圆形布局，内圈低密度(暗/小)、外圈高密度(亮/大) |
| 切换延迟 | < 500ms 完成所有粒子重排 |

**失败判定**: 若切换后面板重叠或粒子缺失 → 布局计算错误（MAJOR）。

### 期望 5: 颜色图例显示精确 hex 值

**操作**: 查看右侧「颜色图例」面板。

**量化标准**:
| 检查项 | 预期 |
|--------|------|
| 四种类型均有图例 | Tiberium, Ore, Spice, Gems |
| hex 值精度 | 格式 #RRGGBB，数值与渲染颜色一致 |
| 密度级别 | 图例显示 D1, D4, D7, D10 (4 个采样点) |
| 变体标签 | 显示 V0, V1, V2, V3 |

**失败判定**: 若图例颜色与实际渲染不符 → 颜色计算不一致（MAJOR）。

## 检验流程

### 准备工作

1. 打开测试页面：`http://localhost:5173/test/resource/color-mapping/`
2. 确认环境信息栏显示 `Babylon.js` + `WebGL 2.0`
3. 默认状态：网格布局，最大密度 10
4. 确认看到四个矩形面板（绿/金/橙/紫），每个面板有多行彩色方块

### 步骤一：颜色类型对比

1. 找到标记为绿色的面板（Tiberium）：
   - 左端应为深绿色，右端应为亮绿色
   - 对照颜色图例中的 hex 值
2. 找到标记为金色的面板（Ore）：
   - 左端应为深棕金色，右端应为亮金色
3. 找到标记为橙红色的面板（Spice）：
   - 左端应为深红/棕色，右端应为亮橙红色
4. 找到标记为紫色的面板（Gems）：
   - 左端应为深紫色，右端应为亮紫红色
5. 确认四种类型颜色完全可区分（无混淆）

**预期**: 符合期望 1 → 继续

### 步骤二：密度渐变验证

1. 在 Tiberium 面板中，从左到右逐列扫视：
   - 确认每列颜色严格递增（越来越亮）
   - 确认无跳跃（相邻列差异小）
   - 确认无逆序（最右列必须最亮）
2. 在 Ore 面板中重复相同检查
3. 在 Spice、Gems 面板中重复

**预期**: 符合期望 3 → 继续

### 步骤三：变体区分度验证

1. 在 Tiberium 面板中，从上到下逐行扫视：
   - 确认同一列（相同密度）的不同行颜色有肉眼可辨差异
   - 差异应为细微色相偏移（非亮度差异）
2. 点击「比较调色板 (原色 vs 偏移)」：
   - 同一面板中所有行变为相同颜色（变体偏移被禁用）
   - 密度渐变仍然保持
3. 再次点击（恢复）：
   - 变体颜色差异恢复

**预期**: 符合期望 2 → 继续

### 步骤四：布局模式切换

1. 选择「并排 (Side-by-side)」布局：
   - 面板排列为 2×2 网格
   - 间距均匀，无重叠
2. 选择「密度色轮」：
   - 四个圆形排列
   - 内圈暗且小，外圈亮且大
3. 恢复「网格 (Grid)」布局

**预期**: 符合期望 4 → 继续

### 步骤五：图例验证

1. 查看右侧「颜色图例」面板
2. 对照渲染区域：
   - Tiberium D1 V0 hex 值与面板中对应位置颜色一致
   - 每个图例颜色 swatch 与实际渲染匹配
3. 最大密度改为「12」→ 图例应立即更新

**预期**: 符合期望 5 → 继续

### 边界/异常测试

1. **最大密度切换**：最大密度改为 12 → 面板列数增加，颜色范围不变
2. **缩放观察**：滚轮放大面板中的单个 cell → 颜色应均匀，无锯齿色块
3. **切换触发**：快速连续切换 5 次布局模式 → 无崩溃
4. **色轮 360 度**：「密度色轮」中外圈应包含该类型所有变体色彩

## 技术背景

### 资源类型颜色定义（基于 OpenRA C&C mod）

| 资源类型 | 最大密度 | 变体数 | 序列模板 |
|---------|:---:|:---:|---------|
| Tiberium | 12 | 3-4 | `tib{m}{v}` 如 `tib01`, `tib02`, `tib03` |
| Ore | 12 | 3-4 | `ore{m}{v}` 如 `ore01`, `ore02` |
| Spice | 12 | 3 | `spice{m}{v}` (16 frames per sequence) |
| Gems | 12 | 3-4 | `gems{m}{v}` (稀有高价值) |

### 密度 → 帧映射规则

- 每个 sequence 包含 8-16 帧精灵（取决于资源类型和 mod 配置）
- 帧 0 = 最小密度（密集度最低的精灵）
- 帧 N-1 = 最大密度（密集度最高的精灵）
- `frame = lerp(0, N-1, density, maxDensity)` → 线性插值
