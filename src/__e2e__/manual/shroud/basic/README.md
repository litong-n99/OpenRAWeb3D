## 期望结果 (Expected Results)

1. **三态可见性渲染**: 三种遮挡状态在 3D 场景中清晰可辨，颜色与透明度严格符合规格。
   - Hidden (0): `rgba(0, 0, 0, 1.0)` -- 完全不透明黑色，地形完全不可见
   - Explored (1): `rgba(15, 15, 15, 0.55)` -- 半透明暗灰色（战争迷雾），地形隐约可见
   - Visible (2): `alpha = 0` -- 完全透明，地形棋盘格清晰可见
   - 可量化指标: 在 512x512 纹理分辨率下，每个 Cell 为 32x32 像素，颜色必须均匀无噪点

2. **边缘混合 (Edge Blending)**：相邻 Cell 状态不同时，边界处渲染渐变过渡条带。
   - 渐变宽度: 4 像素 (Canvas2D linearGradient)
   - 渐变方向: 水平边界为水平渐变，垂直边界为垂直渐变
   - 可量化指标: 同状态相邻 Cell 之间**无渐变线**（边界不可见）；不同状态相邻 Cell 之间**有渐变线**（4px 宽条带，从一侧 alpha 过渡到另一侧 alpha）
   - 可量化指标: 对角线角点 (cell 与 TopLeft/TopRight/BottomRight/BottomLeft 邻居) 的过渡通过正交边界的渐变间接覆盖

3. **动态更新性能**：画笔拖拽改变 Cell 状态时，覆盖纹理即时重绘。
   - 可量化指标: 单次 Canvas2D 重绘延迟 < 50ms（256 个 Cell + 边缘渐变），人眼感知为即时更新
   - 可量化指标: 连续拖拽时 FPS 稳定在 55-60，无帧率突降或画面撕裂
   - 可量化指标: 无闪烁（上一帧残留消失）、无残影（旧状态不留痕迹）

4. **地形透出验证**：Visible 区域下方的地形层必须完全可见。
   - 地形层为 8x4 世界单位（257 顶点）绿色棋盘格 `Ground` Mesh，颜色交替 `#1a5c1a` / `#2a7c2a`
   - 可量化指标: 当所有 Cell 设为 Visible 时，256 个棋盘格全部清晰可辨
   - 可量化指标: 当所有 Cell 设为 Explored 时，棋盘格可见但被 55% 暗灰色滤镜覆盖

5. **状态统计精确性**：信息栏实时显示三种状态的 Cell 数量。
   - 可量化指标: Hidden + Explored + Visible = 256（16x16 网格总和不变）
   - 可量化指标: 全部 Hidden 预设 → Hidden=256, Explored=0, Visible=0；全部 Visible → Hidden=0, Explored=0, Visible=256

## 检验流程

### 1. 准备工作

- 打开测试页面: `http://localhost:5173/test/shroud/basic/`
- 确认环境信息栏显示 **"引擎: WebGL 2.0"**
- 设置屏幕分辨率为 1920x1080 (1x 缩放)
- 确认页面加载后网格全部为黑色 (Hidden 状态)，右上角面板显示期望结果

### 2. 步骤一: 三态可见性逐一验证

- 操作: 点击 "全部可见" 按钮
- 观察点:
  - 黑色覆盖层消失，露出完整的绿色棋盘格地形
  - 信息栏: Hidden=0, Explored=0, Visible=256
- 预期: ✅ 黑色完全消除，棋盘格 256 格清晰可辨

- 操作: 点击 "全部探索" 按钮
- 观察点:
  - 覆盖层变为半透明暗灰色 (`rgba(15,15,15,0.55)`)
  - 棋盘格可见但被暗灰色滤镜覆盖
  - 信息栏: Hidden=0, Explored=256, Visible=0
- 预期: ✅ 暗灰色均匀覆盖，无局部颜色异常

- 操作: 点击 "全部隐藏" 按钮
- 观察点:
  - 覆盖层变为完全不透明黑色
  - 棋盘格完全不可见
  - 信息栏: Hidden=256, Explored=0, Visible=0
- 预期: ✅ 纯黑覆盖，地形完全不可见

### 3. 步骤二: 圆形揭示模式验证

- 操作: 点击 "圆形揭示" 预设按钮
- 观察点:
  - 场景中心出现圆形可见区域 (半径 5 Cell, 中心坐标 8,8)
  - 可见区域外是暗灰色探索环 (半径 3 Cell)
  - 最外层是黑色隐藏区域
  - 三个状态形成同心圆状分布
- 预期: ✅ 三态同时呈现，边界清晰，渐变过渡条带可见 (Hidden↔Explored 和 Explored↔Visible 边界处)

### 4. 步骤三: 画笔交互验证

- 操作: 确认画笔模式为 "显示 (=2)" (按钮高亮)，画笔半径为 2
- 操作: 在网格上拖拽鼠标
- 观察点:
  - 拖拽路径上的 Cell 即时变为透明（Visible），棋盘格透出
  - 拖拽停止后无残留闪烁
  - 信息栏 Hidden/Explored/Visible 计数实时更新
- 预期: ✅ 拖拽即时响应，无延迟感 (<50ms)，路径清晰连续

- 操作: 切换画笔模式为 "隐藏 (=0)" (按键盘 3)
- 操作: 在已揭示区域拖拽
- 观察点:
  - Visible 区域恢复为纯黑 Hidden
  - 边界处渐变过渡可见
- 预期: ✅ 状态可逆，隐藏操作与揭示操作对称

- 操作: 切换画笔模式为 "探索 (=1)" (按键盘 2)
- 操作: 在 Hidden 区域拖拽
- 观察点:
  - Hidden 变为半透明暗灰色
  - 边界处有渐变过渡
- 预期: ✅ Explored 与 Hidden/Visible 均有渐变边界

### 5. 步骤四: 边缘混合详细检查

- 操作: 点击 "圆形揭示" 预设
- 操作: 使用滚轮将摄像机缩放到近距离 (约 0.5x zoom)，使单个 Cell 清晰可见
- 观察点:
  - Hidden↔Explored 边界: 可见 4px 渐变条带 (从 `rgba(0,0,0,1)` 到 `rgba(15,15,15,0.55)`)
  - Explored↔Visible 边界: 可见 4px 渐变条带 (从 `rgba(15,15,15,0.55)` 到 `rgba(0,0,0,0)`)
  - Hidden↔Visible 直接边界: 可见 4px 渐变条带 (从 `rgba(0,0,0,1)` 到 `rgba(0,0,0,0)`)
  - 同状态 Cell 之间: **无**渐变线
- 预期: ✅ 渐变条带宽度均匀 (~4px)，方向正确，无缺失或偏移

### 6. 步骤五: 单元格检查器验证

- 操作: 将鼠标悬停在不同状态的 Cell 上方
- 观察点:
  - 右下角检查器面板显示当前 Cell 坐标和状态
  - Visible 行显示 "是" 或 "否"，Explored 行显示 "是" 或 "否"
  - 坐标值随鼠标移动实时变化
- 预期: ✅ 悬停信息与实际视觉状态一致

### 7. 边界/异常测试

- **边界 A - 快速切换预设**: 连续快速点击 "全部可见" → "全部隐藏" → "全部可见" (重复 5 次)
  - 预期: ✅ 无崩溃、无 WebGL 上下文丢失、纹理切换即时

- **边界 B - 极端视角**: 将摄像机旋转至正上方俯视 (天顶角 < 5 度)
  - 预期: ✅ 纹理正常显示，无透视变形导致的摩尔纹

- **边界 C - 边缘画笔**: 将画笔拖拽到网格边缘 (第 0 行或第 15 行)
  - 预期: ✅ 边缘 Cell 正常更新，边界外无越界绘制或错误

- **边界 D - 大半径画笔**: 将画笔半径设为 6 (最大值)，在网格中央拖拽
  - 预期: ✅ 大范围更新流畅，FPS 保持 > 50，无卡顿
