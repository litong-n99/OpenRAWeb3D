> OpenRA 对照: `HardwarePalette.cs`, `PlayerColorRemap.cs`, `Palette.cs`, `Color.cs`  
> 创建日期: 2026-06-04

## 测试目标

本测试页面验证渲染管线中**调色板系统**的视觉正确性。自动化单元测试可以验证数据结构（uint32 ARGB 值）和数学函数（sRGB/线性转换、HSV/RGB 转换），但以下关键行为必须由人工肉眼判断：

1. **BGRA→RGBA 字节交换**：调色板 CPU 缓冲区为小端 ARGB（即 BGRA 字节序），上传到 GPU 纹理时需执行 `swapRB()` 交换 R/B 通道。若交换错误，红色和蓝色通道将互换，整个游戏的色调将完全错误。
2. **调色板索引颜色精度**：着色器使用 `floor(index * 255.0 + 0.5)` 将浮点纹理坐标精确映射为整数索引。浮点精度误差可能导致相邻索引的颜色混合（颜色偏移 1 个索引位）。
3. **PlayerColorRemap HSV 重映射**：玩家颜色替换在 HSV 色彩空间中进行，涉及 sRGB→线性→HSV→新HSV→线性→sRGB 的完整转换链。任何环节的数学错误都会导致颜色失真。

## B. 期望结果（可量化验收标准）

### 期望 1: 梯度调色板无色彩偏移、无通道互换

**操作**: 选择「合成渐变 (R→G→B 色带)」调色板，观察左侧 ORIGINAL PALETTE 面板。

**观察点**:
- 索引 0-84 区域应呈现从**纯黑 (#000000) 到纯红 (#FF0000)** 的平滑红色渐变
- 索引 85-169 区域应呈现从**纯黑 (#000000) 到纯绿 (#00FF00)** 的平滑绿色渐变
- 索引 170-254 区域应呈现从**纯黑 (#000000) 到纯蓝 (#0000FF)** 的平滑蓝色渐变
- 索引 255 应为**纯白 (#FFFFFF)**

**量化标准**:
| 检查项 | 预期颜色 (HEX) | 容差 |
|--------|---------------|------|
| 索引 0 | `#000000` | 精确匹配 |
| 索引 42 (红带中点) | `#7F0000` (±#010000) | 1 单位 RGB |
| 索引 84 (红带终点) | `#FF0000` | 精确匹配 |
| 索引 85 (绿带起点) | `#000000` | 精确匹配 |
| 索引 127 (绿带中点) | `#007F00` (±#000100) | 1 单位 RGB |
| 索引 169 (绿带终点) | `#00FF00` | 精确匹配 |
| 索引 170 (蓝带起点) | `#000000` | 精确匹配 |
| 索引 212 (蓝带中点) | `#00007F` (±#000001) | 1 单位 RGB |
| 索引 254 (蓝带终点) | `#0000FF` | 精确匹配 |
| 索引 255 | `#FFFFFF` | 精确匹配 |

**失败判定**: 若红色区域呈现蓝色调、蓝色区域呈现红色调 → BGRA→RGBA 字节交换错误（BLOCKER）。若渐变出现可见色带断裂（单色跳变 > 15 RGB 单位）→ 纹理精度或采样模式错误（MAJOR）。

### 期望 2: 已知参考色调色板颜色值与标注一致

**操作**: 选择「已知参考色 (50 个精确颜色)」调色板，观察左侧面板，对比右下角「参考色验证点」列表。

**量化标准**:
| 索引 | 预期颜色 | 肉眼判定标准 |
|------|---------|-------------|
| 0 | `#000000` 纯黑 | 与页面背景色 (#1a1a2e) 应有明显区分 |
| 1 | `#FF0000` 纯红 | 应为鲜艳正红色，非暗红或橙红 |
| 2 | `#00FF00` 纯绿 | 应为鲜艳正绿色，非黄绿或青绿 |
| 3 | `#0000FF` 纯蓝 | 应为鲜艳正蓝色，非紫蓝或青蓝 |
| 4 | `#FFFFFF` 纯白 | 应为纯白，无偏色 |
| 10 | `#FFFF00` 黄 | 应为正黄色，非橙黄或柠檬黄 |
| 11 | `#00FFFF` 青 | 应为正青色，非蓝绿 |
| 12 | `#FF00FF` 品红 | 应为正品红，非紫色 |
| 60 | 完全透明 | 应显示为棋盘格图案（灰/深灰交替），不显示任何颜色 |

**失败判定**: 若索引 1（红色）显示为蓝色，索引 3（蓝色）显示为红色 → 通道交换错误（BLOCKER）。若透明索引 60 显示为纯黑色而非棋盘格 → Alpha 处理错误（MAJOR）。

### 期望 3: PlayerColorRemap 颜色偏移效果即时可见

**操作**: 选择「C&C TD 模拟」调色板，设置玩家颜色为红色 (#e94560)，点击「应用重映射」。

**观察点**:
- 右侧 REMAPPED PALETTE 面板中，索引 **176-191**（默认重映射范围）的颜色应从蓝灰色系变为**红色系色调**
- 左侧 ORIGINAL PALETTE 面板中，索引 176-191 的颜色应保持为蓝灰色系不变
- 右侧面板中索引 0-175 和 192-255 的颜色应与左侧面板完全相同（非重映射索引不受影响）
- 重映射应在**点击按钮后 200ms 内完成更新**，不应有可见延迟或闪烁

**量化标准**:
| 观察项 | 预期 | 容差 |
|--------|------|------|
| 重映射响应延迟 | < 200ms | 肉眼不应感知延迟 |
| 重映射区域边界 | 索引 175→176 有明显颜色跳变 | 边界清晰无模糊 |
| 非重映射区域一致性 | 左/右面板索引 0-175 颜色完全相同 | 肉眼不可区分 |
| 色调偏移方向 | 蓝灰 → 红粉 | 明显可辨 |

**失败判定**: 若点击「应用重映射」后右侧面板完全无变化 → PlayerColorRemap 逻辑错误（BLOCKER）。若非重映射区域颜色也发生变化 → 索引过滤错误（BLOCKER）。若重映射后出现纯黑或纯白块 → 亮度缩放计算溢出（MAJOR）。

### 期望 4: FPS 稳定性

**操作**: 在任意调色板下，快速拖动「亮度缩放」滑块（0-2 范围）或连续切换调色板。

**量化标准**:
- FPS 应稳定在 **55-60 fps**（60Hz 显示器）或显示器刷新率 -5 fps 以内
- 切换调色板时帧率下降不超过 **5 fps**，且在 1 秒内恢复
- 拖动滑块时不应出现画面撕裂或帧跳跃

**失败判定**: 若 FPS 持续低于 30 → 性能退化（MAJOR）。若切换调色板时页面冻结超过 200ms → 主线程阻塞（MAJOR）。

### 期望 5: 显示选项即时生效

**操作**: 分别切换「显示调色板索引号」和「显示网格线」复选框。

**量化标准**:
- 复选框状态变更后 **100ms 内**两个面板同时更新
- 索引号文字在深色色块上应为白色，在浅色色块上应为黑色（保证可读性）
- 网格线应为半透明白色，线宽约 0.5px，不遮挡色块颜色

## 检验流程

### 准备工作

1. 打开测试页面：
   - 开发模式: `http://localhost:5173/src/__e2e__/manual/hardware-palette/color-accuracy/`
   - 或通过文件路径直接访问 index.html
2. 确认页面底部**环境信息栏**显示：
   - 引擎: `Babylon.js vX.Y.Z / WebGL 2.0`（非 WebGL 1.0）
   - FPS: 显示数值（非 `-`）
   - 视口: 匹配当前浏览器窗口尺寸
3. 设置屏幕分辨率为 **1920x1080**（1x 缩放），关闭浏览器夜间模式/色彩滤镜
4. 确保显示器已校准或使用标准 sRGB 色彩配置文件

### 步骤一：梯度调色板基础颜色验证

1. 确认调色板下拉菜单选中「合成渐变 (R→G→B 色带)」
2. 观察左侧 **ORIGINAL PALETTE** 面板（16x16 色块网格）
3. **验证红色渐变区**：
   - 找到索引 0-84 区域（网格顶部 5 行 + 第 6 行前 5 列）
   - 从左上角纯黑开始，应平滑过渡到第 6 行第 4 列的纯红
   - 检查：中间不应出现绿色或蓝色色调
4. **验证绿色渐变区**：
   - 找到索引 85-169 区域（第 6 行第 5 列到第 11 行第 4 列）
   - 从纯黑过渡到纯绿
   - 检查：中间不应出现红色或蓝色色调
5. **验证蓝色渐变区**：
   - 找到索引 170-254 区域（第 11 行第 5 列到第 16 行第 2 列）
   - 从纯黑过渡到纯蓝
   - 检查：中间不应出现红色或绿色色调
6. **验证索引 255**：网格右下角色块应为纯白

**预期**: 全部符合期望 1 的量化标准 → 继续  
**异常**: 出现通道交换（红蓝互换）→ 记录为 **BLOCKER**，提交 issue 并附截图

### 步骤二：参考色调色板精确颜色验证

1. 调色板下拉菜单切换到「已知参考色 (50 个精确颜色)」
2. 观察左侧面板，找到以下关键索引（可参考右下角参考色列表）：
   - 索引 0（网格左上角）：应为纯黑 `#000000`
   - 索引 1（索引 0 右侧）：应为纯红 `#FF0000`
   - 索引 2：应为纯绿 `#00FF00`
   - 索引 3：应为纯蓝 `#0000FF`
   - 索引 4：应为纯白 `#FFFFFF`
   - 索引 60（第 3 行末尾附近）：应显示**棋盘格图案**（透明色）
3. 肉眼对比索引 1（红色）和索引 3（蓝色）：
   - 红色应明显偏暖（R 通道最高）
   - 蓝色应明显偏冷（B 通道最高）
   - 两者不应有任何混淆
4. 检查索引 10（黄）、11（青）、12（品红）：每个都应色彩鲜明，互不混淆

**预期**: 全部符合期望 2 的量化标准 → 继续  
**异常**: 若红蓝混淆 → 记录为 **BLOCKER**（BGRA↔RGBA 交换错误）

### 步骤三：PlayerColorRemap 重映射效果验证

1. 调色板切换到「C&C TD 模拟」
2. 玩家颜色选择器设置为**红色**（如 `#e94560`）
3. 确认重映射范围滑块显示 `176-191`
4. 亮度缩放保持 `1.00`
5. 定位索引 176-191 在左侧面板中的位置（第 12 行，大约中间偏右）
   - 应显示为**蓝灰色**系渐变
6. 点击「**应用重映射 (Apply Remap)**」按钮
7. 观察右侧 **REMAPPED PALETTE** 面板：
   - 索引 176-191 区域应立即变为**红色系色调**（粉色到暗红）
   - 观察边界：索引 175 和 192 应与左侧原色一致
   - 索引 176-191 以外的所有颜色应与左侧完全相同
8. 更改玩家颜色为**蓝色**（如 `#3366ff`）→ 点击应用
   - 索引 176-191 应变为蓝色系色调
9. 更改玩家颜色为**绿色**（如 `#33cc33`）→ 点击应用
   - 索引 176-191 应变为绿色系色调
10. 调整亮度缩放为 `0.50` → 点击应用
    - 重映射区域应明显变暗（亮度减半）
11. 调整亮度缩放为 `1.50` → 点击应用
    - 重映射区域应明显变亮
12. 点击「**重置为原始调色板**」→ 右侧面板应与左侧完全一致

**预期**: 全部符合期望 3 的量化标准 → 继续  
**异常**: 若重映射无效 → 记录为 **BLOCKER**

### 步骤四：FPS 性能验证

1. 观察右下角 FPS 计数器（稳定后应显示 55-60）
2. 快速拖动亮度缩放滑块（0-2 范围内来回拖动 5 次）
3. FPS 应保持 ≥ 50，不出现掉到 30 以下的情况
4. 快速连续切换调色板（下拉菜单连续变更 5 次）
5. 切换期间 FPS 不应降至 0（冻结）

**预期**: 全部符合期望 4 的量化标准 → 继续  
**异常**: 若 FPS 持续 < 30 → 记录为 **MAJOR**

### 步骤五：显示选项验证

1. 取消勾选「显示调色板索引号」
   - 两个面板的色块上的数字应立即消失（<100ms）
2. 重新勾选「显示调色板索引号」
   - 数字应立即恢复，且在深色/浅色块上有正确的对比色
3. 取消勾选「显示网格线」
   - 色块之间的白色分割线应立即消失
4. 使用缩放滑块调整放大倍数（0.5x → 4.0x）
   - 两个面板应同步缩放，色块无模糊或像素化失真（DynamicTexture 使用 NEAREST 采样）

**预期**: 全部符合期望 5 的量化标准 → 继续

### 边界/异常测试

1. **重映射范围边界**：设置范围为 `0-0`（仅索引 0），应用重映射 → 仅索引 0 应变化
2. **重映射全部索引**：设置范围为 `0-255`，应用重映射 → 所有颜色应统调
3. **极端亮度缩放**：设置亮度缩放为 `0.00` → 重映射区域应全黑
4. **极端亮度缩放**：设置亮度缩放为 `2.00` → 重映射区域应非常亮（可能有截断到 255 的白色区域）
5. **窗口大小调整**：缩小浏览器窗口到 800x600 → 视口信息应自动更新，纹理应正常显示
6. **浏览器缩放**：将浏览器缩放到 150% → 纹理不应出现模糊或锯齿（NEAREST 采样）

## 技术背景

### 本测试页面覆盖的关键迁移风险

| 风险 | OpenRA 原始行为 | Babylon.js 迁移实现 | 验证方式 |
|------|----------------|-------------------|---------|
| BGRA→RGBA 字节交换 | OpenGL 内部格式为 BGRA，无需交换 | `swapRB()` 在 CPU 端将 BGRA 转为 RGBA 后上传 | 参考色调色板（期望 2） |
| 调色板索引浮点精度 | `GL_NEAREST` 采样 + 整数索引 | `NEAREST_SAMPLINGMODE` + `floor(i*255+0.5)` | 梯度平滑性（期望 1） |
| PlayerColorRemap HSV 重映射 | C# Color.RgbToHsv/HsvToRgb | TS rgbToHsv/hsvToRgb + toLinear/fromLinear | 重映射色调偏移（期望 3） |
| 纹理上传格式 | `GL_RGBA8` + `GL_UNSIGNED_BYTE` | `RawTexture.CreateRGBATexture()` | 所有颜色验证 |
| DynamicTexture 性能 | N/A（OpenRA 无此概念） | 2D Canvas → GPU 纹理上传 | FPS 稳定性（期望 4） |

### 关于 HardwarePalette 在完整渲染管线中的角色

```
ImmutablePalette (CPU, 256×uint32)
    │
    ▼
HardwarePalette (CPU+GPU 桥接)
    ├── _buffer: Uint8Array (256×N RGBA, BGRA→RGBA swapped)
    ├── _texture: RawTexture (256×N, NEAREST, no mipmap)
    └── _colorShiftsTexture: RawTexture (2×N, Float32)
         │
         ▼
    combined.frag (GPU 着色器)
         │  采样 paletteTexture[floor(index*255+0.5)]
         │  应用 ColorShift HSV 偏移
         ▼
    最终像素颜色
```

本测试页面**绕过着色器**，直接使用 DynamicTexture + 2D Canvas 渲染调色板数据，用于验证 CPU 端数据流（Palette → HardwarePalette buffer → 颜色值）的正确性。完整的 GPU 着色器管线验证需要额外的着色器验收测试页面。
