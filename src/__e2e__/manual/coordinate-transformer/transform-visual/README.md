# CoordinateTransformer — WPos ↔ Vector3 转换可视化验证

**OpenRA 对照**: `src/OpenRA.Game/CoordinateTransformer.ts` (新文件, 无直接 C# 对照)  
**测试重点**: WPos → Vector3 坐标映射正确性、缓存命中率、实时交互、往返精度  
**坐标系约定**:
- WAngle 0 = 北, 逆时针递增 (在转换中不直接涉及角度)
- OpenRA (X→右, Y→下(南), Z→高度) → Babylon.js (X→右, Y→上, Z→前(北))
- WPos.X → Vector3.x (1/1024 缩放)
- WPos.Y → Vector3.z (1/1024 缩放) -- 南-北映射到深度轴
- WPos.Z → Vector3.y (1/512 缩放) -- 高度映射到 Y 轴

## 期望结果 (Expected Results)

### 1. WPos → Vector3 映射正确

根据 CoordinateTransformer 实现，映射关系为:
- `Vector3.x = WPos.X * WORLD_SCALE` (WORLD_SCALE = 1/1024 ≈ 0.000977)
- `Vector3.y = WPos.Z * HEIGHT_SCALE` (HEIGHT_SCALE = 1/512 ≈ 0.001953)
- `Vector3.z = WPos.Y * WORLD_SCALE`

- **可量化标准**: WPos(10240, 0, 0) → Vector3.x = **10.000000**
- **可量化标准**: WPos(0, 0, 512) → Vector3.y = **1.000000** (高度 1 Babylon 单位)
- **可量化标准**: WPos(0, 10240, 0) → Vector3.z = **10.000000**
- **可量化标准**: WPos(5120, 5120, 512) → Vector3 = **(5.0, 1.0, 5.0)**
- **可量化标准**: 球体位置在参考网格中心单元格上方 (grid pos 5,1,5)

### 2. 实时交互响应

- **可量化标准**: 拖动任意滑块后，3D 球体位置在 **50ms** 内更新
- **可量化标准**: 同时显示 WPos 值和对应 Vector3 值，格式为小数点后 **6 位**
- **可量化标准**: 按箭头键调整 WPos 时，球体平滑移动（步进 64 su = 0.0625 Babylon 单位）

### 3. 缓存命中统计

CoordinateTransformer 使用 LRU 缓存（最大 1000 条目）加速重复坐标查询。

- **可量化标准**: 同一 WPos 值查询 2 次后，缓存命中率应 ≥ **50%**
- **可量化标准**: 点击 "清除缓存" 后缓存大小应为 **0**
- **可量化标准**: 连续拖动滑块（产生不同坐标）时，缓存大小从 0 增长，到达 **CACHE_SIZE=1000** 后稳定
- **可量化标准**: 使用预设按钮跳转到之前访问过的坐标时，缓存命中

### 4. 往返转换精度

- **可量化标准**: WPos → Vector3 → WPos 往返误差 ≤ **3 子单位** (整数 round 的最大误差)
- **可量化标准**: 极端坐标 (0,0,0) 和 (10240,10240,4096) 往返后 X/Y/Z 差值 ≤ 2

### 5. 3D 场景渲染

- **可量化标准**: 参考网格显示 **5x5 个单元格**，每个 1 Babylon 单位 (1024 su)
- **可量化标准**: 坐标轴 RGB=XYZ 颜色正确 (X=红, Y=绿, Z=蓝)
- **可量化标准**: FPS 稳定在 **55-60**（简单场景）

## 检验流程

### 1. 准备工作

- 打开测试页面: `http://localhost:5173/test/coordinate-transformer/transform-visual/`
- 确认环境信息栏显示 **"WebGL 2.0"** 引擎
- 设置屏幕分辨率 1920x1080 (1x 缩放)
- 确认球体初始位于地图中心 (Vector3 ≈ 5.0, 1.0, 5.0)

### 2. 步骤一: WPos → Vector3 映射验证

- 操作: 点击 "原点 (0,0,0)" 预设
- 观察点: 相机视角平滑移动到坐标轴原点，橙色球体位于原点 (Vector3.x=0, y=0, z=0)
- 确认: ✅ WPos 显示 "0, 0, 0"，Vector3 显示 "0.000000, 0.000000, 0.000000"

- 操作: 点击 "角落 (10240,10240,0)" 预设
- 观察点: 相机视角平滑移动到参考网格右上角，橙色球体位于 (Vector3.x=10.0, y=0, z=10.0)
- 确认: ✅ Vector3.x = 10.000000, Vector3.z = 10.000000

- 操作: 点击 "高处 (2560,7680,2048)" 预设
- 观察点: 相机视角平滑移动到高处，橙色球体位于 Vector3.y = 4.0 (2048/512 = 4)
- 确认: ✅ 球体 Y 高度 = 4.000000，橙色垂线从球体连到地面投影点

### 3. 步骤二: 实时交互验证

- 操作: 缓慢拖动 X 滑块从 0 到 10240
- 观察点: 球体沿红色 X 轴方向平滑移动
- 操作: 使用键盘方向键 (←↑↓→) 步进调整位置
- 观察点: 球体每次移动 0.0625 单位 (64 su)
- 操作: 按住 Shift + 方向键进行大步进 (256 su = 0.25 单位)
- 预期: ✅ 球体响应 < 50ms, 位置平滑更新

### 4. 步骤三: 缓存统计验证

- 操作: 点击 "清除缓存" 按钮
- 观察点: 缓存统计显示 0 条目，命中率 "0.0% hit"
- 操作: 依次点击以下预设，每点一次观察缓存面板变化：

| 点击顺序 | 预设按钮 | WPos 坐标 | 预期缓存行为 | 预期查询总数 | 预期命中率 |
|:---:|:---|:---|:---|:---:|:---:|
| 1 | "原点 (0,0,0)" | 首次访问 (0,0,0) | 2 次 miss（wPos→Vec + Vec→WPos 均为新值） | 2 | 0% |
| 2 | "中心 (5120,5120,0)" | 首次访问 (5120,5120,0) | 2 次 miss（全新坐标） | 4 | 0% |
| 3 | "角落 (10240,10240,0)" | 首次访问 (10240,10240,0) | 2 次 miss（全新坐标） | 6 | 0% |
| 4 | "中心 (5120,5120,0)" | 已在步骤 2 访问过 | 2 次 hit（缓存命中，cache size 不变） | 8 | 25% |

- 解释: 每次点击执行 wPosToVector3 + vector3ToWPos 往返共 2 次查询。首次访问新坐标必然 miss，只有重复访问已查过的坐标才 hit。步骤 4 的两条查询全部命中。
- 预期: ✅ 步骤 1-3 缓存大小逐步增长（每步 +2）；步骤 4 缓存大小不变；全局命中率 25%（2/8）；cache size ≤ CACHE_SIZE (1000)

### 5. 步骤四: 参考网格对齐验证

- 操作: 确认参考网格可见 (蓝色线)
- 操作: 调整 WPos 使 Vector3 恰好落在网格交叉点
- 例如: WPos(1024, 1024, 0) → Vector3(1.0, 0, 1.0)
- 观察点: 球体与网格中心点完全对齐
- 操作: WPos(5120, 5120, 512) → Vector3(5.0, 1.0, 5.0)
- 观察点: 球体在网格中心，高度 1 单位
- 预期: ✅ 球体位置精准对齐网格线交叉点

### 6. 步骤五: 往返精度验证

- 操作: 打开浏览器控制台
- 操作: 执行 `__testHarness.runStressTest()`
- 观察点: 控制台输出 200 次随机 WPos 往返转换耗时
- 观察点: 平均每次转换耗时 < 0.1ms
- 操作: 拖到极端值 (0,0,0) 和 (10240,10240,4096)
- 观察点: Vector3 显示值精度至 6 位小数
- 预期: ✅ 往返误差 ≤ 3 su, 平均转换 < 0.1ms

### 7. 边界/异常测试

- **边界 A - 极端缩放**: 滚轮缩放至最近/最远
  - 预期: ✅ 球体和网格始终可见，无裁剪

- **边界 B - 快捷键**: 按 G 切换网格显示/隐藏
  - 预期: ✅ 网格显示切换 < 100ms, 无闪烁

- **边界 C - 快速拖动**: 连续快速拖动 3 个滑块
  - 预期: ✅ 无卡顿, FPS 保持 > 55

- **边界 D - 缓存溢出**: 拖动滑块产生 > 1000 个不同坐标值
  - 预期: ✅ 缓存大小稳定在 1000, 旧条目被正常逐出
