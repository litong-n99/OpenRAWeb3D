## 测试目标

本测试页面验证 SpriteRenderer 中 ThinInstancesGroup 使用的 Billboard 模式。在 RTS 游戏中，单位精灵需设置为 `BILLBOARDMODE_Y` —— 精灵始终围绕 Y 轴旋转以面向摄像机，但保持直立（不会倾倒）。若 billboard 模式错误，摄像机旋转时精灵会出现侧面/背面暴露或消失的问题。

---

## B. 期望结果（可量化验收标准）

### 期望 1: BILLBOARDMODE_Y — 精灵始终面向摄像机（仅 Y 轴旋转）

**操作**: 默认状态下，观察 5x5 精灵网格（25 个带箭头的彩色方块）。

**观察点**:
- 所有 25 个精灵的**正面始终正对摄像机**（即精灵面朝观察者，平面法线指向摄像机）
- 摄像机在默认 RTS 视角（alpha=-90°, beta=72°）时，精灵正面完全可见，无侧面收缩
- 箭头纹理指向精灵的局部右侧，作为非对称方向标记用于区分正面/背面
- 精灵正面完全可见，无侧面收缩或消失

**量化标准**:
| 检查项 | 预期行为 | 容差 |
|--------|---------|------|
| 默认视角 (alpha=-90°, beta=72°) | 所有 25 个精灵正面正对屏幕，箭头指向右侧 | 肉眼判断 |
| 精灵正面可见性 | 100% 精灵正面完全可见，无侧面遮挡 | 无不可见精灵 |
| 精灵 Y 轴 | 所有精灵保持直立，不倾斜 | 角度偏差 < 5° |

### 期望 2: 摄像机旋转时精灵持续面向摄像机

**操作**: 拖动水平旋转滑块（Alpha）从 -180° 到 0°，或勾选「自动旋转摄像机」。

**观察点**:
- 摄像机在任意 Alpha 角度下，所有精灵正面都始终面向摄像机
- 参照精灵（左下角红色方块，**无** billboard 模式）在摄像机旋转时会露出侧面/背面
- 精灵之间相对位置关系保持不变（网格不扭曲、不漂移）
- 在 alpha=-180°（摄像机从另一侧看）时，精灵应翻转 180° 继续面向摄像机

**量化标准**:
| 检查项 | 预期行为 | 容差 |
|--------|---------|------|
| 摄像机 360° 旋转 | 精灵正面始终面向摄像机 | 在任意角度肉眼验证 |
| 参照精灵对比 | billboard 精灵 vs 无 billboard 参照有明显区别 | 肉眼可辨 |
| 网格完整性 | 25 个精灵保持 5x5 等距排列 | 无漂移/重叠 |

### 期望 3: 俯仰角不影响 billboard 效果

**操作**: 拖动俯仰角滑块（Beta）从 30°（近乎水平）到 150°（近乎顶视）。

**观察点**:
- 在任何俯仰角下，精灵正面始终面向摄像机（法线指向摄像机）
- 在低角度（beta≈30°，近乎水平视角）时，精灵仍清晰可见（不被压缩为线）
- 在高角度（beta≈150°，近乎顶视）时，精灵仍可辨认

**量化标准**:
| 检查项 | 预期行为 | 容差 |
|--------|---------|------|
| 极端俯仰角 (30° | 150°) | 精灵正面仍面向摄像机 | 肉眼判断 |
| 低角度精灵面积 | 精灵可见高度 ≥ 正常高度的 50% | 肉眼判断 |
| 无精灵消失 | 所有 25 个精灵在任何角度都可见 | 0 个不可见 |

### 期望 4: Billboard 模式切换即时生效

**操作**: 从下拉菜单切换 billboard 模式：BILLBOARDMODE_Y → BILLBOARDMODE_ALL → 无 (标准几何体)。

**观察点**:
- 切换到 BILLBOARDMODE_ALL：精灵同时绕 X 和 Y 轴面向摄像机（可能倾倒），与 BILLBOARDMODE_Y 明显不同
- 切换到「无」：精灵变成固定朝向的标准平面，旋转摄像机时露出侧面
- 模式切换应在 **50ms 内** 完成，无闪烁或跳变

**量化标准**:
| 检查项 | 预期行为 | 容差 |
|--------|---------|------|
| 模式切换延迟 | < 50ms | 肉眼不应感知延迟 |
| BILLBOARDMODE_ALL 效果 | 精灵全部转为全向 billboard | 与 Y 模式有明显视觉差异 |
| 无 billboard 效果 | 精灵固定朝向，旋转摄像机时侧面可见 | 肉眼可辨 |

### 期望 5: FPS 稳定性

**操作**: 在「自动旋转摄像机」模式下让场景运行 10 秒。

**量化标准**:
- FPS 应稳定在 **55-60 fps**（60Hz 显示器）或显示器刷新率 -5 fps 以内
- 25 个精灵 + billboard 计算不应对性能产生可见影响

## 检验流程

### 准备工作

1. 打开测试页面：`http://localhost:5173/test/sprite-renderer/sprite-billboarding/`
2. 确认页面底部**环境信息栏**显示：
   - 引擎: `Babylon.js vX.Y.Z / WebGL 2.0`
   - FPS: 显示数值（非 `-`）
3. 设置屏幕分辨率为 **1920x1080**（1x 缩放）

### 步骤一：默认视角验证

1. 确认摄像机为默认 RTS 视角（点击「重置摄像机」确保）
2. 观察 5x5 精灵网格（25 个彩色箭头方块）
3. 确认所有 25 个精灵正面都正对屏幕（箭头应指向右侧，作为正面/背面区分标记）
4. 观察左下角参照精灵（标注「NO BILLBOARD (参照)」）：应为红色箭头，在默认视角下也应正对屏幕
5. 确认地面有灰色网格线和 RGB 坐标轴

**预期**: 符合期望 1 → 继续
**异常**: 若精灵正面未正对屏幕或箭头方向异常 → 记录为 **BLOCKER**

### 步骤二：水平旋转验证

1. 拖动「水平旋转 (Alpha)」滑块从 -90° 缓慢滑动到 -180°
2. 观察精灵网格：
   - billboard 精灵（5x5 网格中心方块）正面应始终面向摄像机（非对称箭头标记保持可见）
   - 参照精灵（左下角）应露出侧面
3. 继续拖动 Alpha 到 0°
4. 勾选「自动旋转摄像机」，观察 360° 旋转过程中精灵正面是否持续面向摄像机

**预期**: 符合期望 2 → 继续
**异常**: 若 billboard 精灵在某角度露出侧面 → 记录为 **BLOCKER**

### 步骤三：俯仰角验证

1. 恢复默认视角
2. 拖动「俯仰角 (Beta)」滑块从 72° 到 30°
3. 观察：精灵正面仍面向摄像机，精灵保持直立
4. 拖动 Beta 到 150°（近乎顶视）
5. 观察：精灵仍可辨认，正面面向摄像机

**预期**: 符合期望 3 → 继续

### 步骤四：Billboard 模式切换

1. 在 billboard 模式下拉菜单中切换到「BILLBOARDMODE_ALL」
2. 旋转摄像机：精灵应同时绕 X 和 Y 轴面向摄像机（不同于 Y 模式）
3. 切换到「无 (标准几何体)」
4. 旋转摄像机：精灵保持固定朝向，露出侧面

**预期**: 符合期望 4 → 继续

### 步骤五：辅助功能验证

1. 取消勾选「显示坐标轴参考」→ 坐标轴应立即消失
2. 重新勾选 → 坐标轴应立即恢复
3. 取消勾选「显示地面网格」→ 网格线应立即消失
4. 使用鼠标滚轮缩放 → 精灵尺寸应随之变化
5. 使用鼠标拖拽平移 → 精灵位置应跟随移动

### 边界/异常测试

1. **摄像机距离极限**：将距离滑块拖到 4→ 精灵应清晰可见（不裁剪）
2. **摄像机距离极限**：将距离滑块拖到 30→ 精灵应仍可辨认（不消失）
3. **快速旋转**：快速拖动 Alpha 滑块 → 精灵不应出现跳变
4. **窗口缩放**：将窗口缩小到 800x600 → 场景应正常渲染
