## 测试目标

本测试页面验证纹理图集系统的两个关键视觉行为：

1. **行式打包布局**：SheetBuilder 使用行式（row-based）矩形打包算法，从左到右在行内排列精灵，当前行空间不足时换行。Indexed 类型每 4 个精灵切换一次通道（R→G→B→A 循环），对应 OpenRA 的 `PumpRect` / `nextChannel` 逻辑。
2. **BGRA→RGBA 字节交换**：CPU 端调色板/纹理缓冲区为 ARGB uint32（小端 = BGRA 字节序），WebGL 纹理内部格式为 RGBA，上传时通过 `swapRB()` 交换红蓝通道。若未执行交换，整个游戏的红色和蓝色将互换。

## B. 期望结果（可量化验收标准）

### 期望 1: 行式打包算法 — 从左到右排列，换行正确

**操作**: 默认设置（BGRA 类型，256x256 Sheet，随机尺寸 20 精灵），观察图集。

**观察点**:
- 精灵从左到右在一行内排列
- 同一行的精灵**底边对齐**（以该行最高精灵为行高基准）
- 当前行剩余空间装不下下一精灵时**自动换行**
- 每个精灵周围有 **1 像素半透明虚线**（表示 margin，防止纹理出血）
- 无精灵重叠

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| 打包方向 | 从左到右 → 换行 → 继续 |
| 行内对齐 | 底边对齐（top = 上一行 bottom + margin） |
| 重叠 | 0 个精灵重叠 |
| 利用率 | 30%-90%（取决于精灵尺寸分布） |

**失败判定**: 若精灵出现重叠 → 打包算法错误（BLOCKER）。若换行后新行 Y 坐标不正确 → 行高计算错误（MAJOR）。

- 通道颜色可明确区分，无混淆
- 通道循环正确：精灵 0→R, 1→G, 2→B, 3→A, 4→R, ...

**量化标准**:

**失败判定**: 若相邻精灵同通道颜色相同却标签不同通道 → 通道分配逻辑错误（MAJOR）。

### 期望 3: BGRA→RGBA 差异对比 — 红蓝互换可见

**操作**: 显示模式切换到「差异对比 (左右分屏)」，选择测试色「纯红」→ 点击「重新打包」。

- 红色(#FF0000) 的 BGRA 字节 = [0, 0, 255, 255]，若未交换则 GPU 读取为 RGBA [0, 0, 255, 255] = 纯蓝

**量化标准**:
| 测试色 | 左侧 (correct) | 右侧 (broken) |
|--------|---------------|---------------|
| 纯红 #FF0000 | 红色 | 蓝色 (#0000FF) |

### 步骤三：BGRA→RGBA 差异对比 —— 验证 R↔B 字节交换

**前置知识：BGRA 字节序**

OpenRA 的 CPU 端使用 32-bit ARGB 颜色值（小端字节序），在内存中的字节排列为 `[B, G, R, A]`：

```
CPU 内存（小端 ARGB uint32）
  示例: ARGB(255, 255, 0, 0) = 纯红 #FF0000
  内存字节: [0x00, 0x00, 0xFF, 0xFF]
  对应:     [  B,    G,    R,    A  ]
```

WebGL 纹理期望的是 RGBA 字节序 `[R, G, B, A]`。因此上传前必须通过 `swapRB()` 将位置 0 和位置 2 的字节交换（B↔R），得到 `[0xFF, 0x00, 0x00, 0xFF]` = `[R=255, G=0, B=0, A=255]` = 纯红，GPU 才能正确渲染。

- **如果 swapRB 执行了**：GPU 读到 `[R=255, G=0, B=0]` → 正确渲染为红色。
- **如果 swapRB 漏掉了**：GPU 把 `[B=0, G=0, R=255]` 当作 `[R=0, G=0, B=255]` 来读 → 渲染成纯蓝色。

简单说：**漏掉 swapRB 会导致游戏中所有红色变成蓝色、所有蓝色变成红色**。绿色不受影响（因为 G 通道位于字节位置 1，swapRB 不碰它）。

**本测试页的差异对比模式**

页面将同一组精灵打包两次：
- 左侧（标注 CORRECT）：swapRB **已执行**，颜色正确
- 右侧（标注 BROKEN）：swapRB **未执行**，R↔B 互换

由于测试页使用 4 种默认通道色（红 / 绿 / 蓝 / 橙）来渲染精灵，差异对比模式下你可以看到每种颜色在 R↔B 交换后的变化。

**操作步骤**

1. Sheet 类型切回「BGRA (4 通道 RGBA 纹理)」
2. 显示模式切换到「差异对比 (左右分屏)」
3. 点击「重新打包」

假设有一个纯红色的精灵（这在实际测试页中不会出现，但原理如此）：

| 测试色 | 左侧（swapRB 已执行） | 右侧（swapRB 未执行） | 原因 |

| 纯红 #FF0000 | 红色 #FF0000 | 蓝色 #0000FF | BGRA `[0,0,255,255]` 被 GPU 误读为 `[R=0,G=0,B=255]` |

## 技术背景

### BGRA→RGBA 字节交换详解

```
CPU 内存（BGRA 字节序，小端 ARGB uint32）:
  值 0xFF0000FF → 字节 [0xFF, 0x00, 0x00, 0xFF]
                  = [B=255, G=0, R=0, A=255]  ← 纯红色

swapRB() 转换后:
  字节 [0x00, 0x00, 0xFF, 0xFF]
  = [R=0, G=0, B=255, A=255]  ← 纯蓝色（因为 R/B 交换了！）

等等，这个推理不对。让我重新来：
纯红 #FF0000 = ARGB(0xFF, 0xFF, 0x00, 0x00)
小端存储: [0x00, 0x00, 0xFF, 0xFF] = [B, G, R, A]
swapRB: 交换位置 0 和 2 → [0xFF, 0x00, 0x00, 0xFF] = [R, G, B, A]

所以：
- BGRA [0x00, 0x00, 0xFF, 0xFF] = B=0, G=0, R=255, A=255
- swapRB → RGBA [0xFF, 0x00, 0x00, 0xFF] = R=255, G=0, B=0, A=255 ✓ 纯红

若未执行 swapRB，GPU 将 BGRA 当作 RGBA 读取:
- GPU 读取字节 [0x00, 0x00, 0xFF, 0xFF]
- 解释为 R=0, G=0, B=255, A=255 = 纯蓝 ✗
```

### SheetBuilder 打包算法伪代码

```
function Allocate(width, height):
  if width==0 or height==0: return emptySprite
  
  for each Sheet:
    if currentX + width + margin > sheet.Width:
      currentX = margin
      currentY += rowHeight + margin
      rowHeight = 0
      if Indexed: nextChannel()
    
    if currentY + height + margin > sheet.Height:
      continue  // try next sheet
    
    result = (sheet, rect(currentX, currentY, width, height), channel)
    currentX += width + margin
    rowHeight = max(rowHeight, height + margin)
    if Indexed: nextChannel()
    return result
  
  allocateNewSheet()
  retry
```

### SheetType 枚举

| 类型 | 值 | 通道数 | 行为 |
|------|---|--------|------|
| Indexed | 1 | 1 (循环 4 通道) | 每通道独立纹理，4 个通道循环使用到一个 Sheet 满 |
| BGRA | 4 | 4 (RGBA 单通道) | 所有精灵共用一个 Sheet，无需通道切换 |
