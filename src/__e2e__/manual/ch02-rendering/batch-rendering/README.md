## 测试目标

本测试页面验证地形精灵层的核心批量渲染行为。TerrainSpriteLayer 管理整个地图的地形瓦片渲染，每格预分配 4 个顶点（Quad），使用脏行集（`Set<number>`）跟踪需要上传到 GPU 的行，仅更新变化部分以最小化 GPU 带宽开销。

自动化单元测试可以验证顶点数组布局、脏行集合操作、Sheet 槽位分配算法，但以下关键行为必须由人工肉眼判断：

1. **批量渲染性能**：在 256-4096 个瓦片同时渲染时，帧率是否稳定在可接受范围。瓦片越多，顶点数据越大，GPU 上传带宽需求越高。
2. **脏行更新正确性**：更新特定行后，仅该行应该发生变化，其他行保持原样。这验证了脏行跟踪是否在正确粒度工作。
3. **Sheet 槽位切换**：切换活跃 Sheet 时，所有瓦片的颜色/外观应统一变化（模拟不同纹理表绑定效果），且变化应在可接受时间窗口内完成。
4. **交互响应**：点击瓦片切换地形类型应即时响应（<100ms），无可见延迟或闪烁。

## B. 期望结果（可量化验收标准）

### 期望 1: 256 瓦片（16x16）渲染 FPS >= 55

**操作**: 默认设置（16x16 地图，棋盘格模式），观察 FPS 计数器。

**量化标准**:
| 检查项 | 预期值 | 容差 |
|--------|--------|------|
| 稳定 FPS | >= 55 fps | 60Hz 显示器下允许偶尔 50-54 |
| 初始加载时间 | < 500ms | 从页面加载到首帧渲染 |
| 内存占用 | 无明显泄漏 | 运行 30 秒 FPS 稳定不下降 |

**失败判定**: 若 FPS 持续低于 30 → 性能退化（MAJOR）。若出现画面撕裂 → 帧同步问题（MAJOR）。

### 期望 2: 脏行更新仅影响目标行

**操作**: 选择「列渐变」地形模式，使用「更新整行」按钮将指定行（如第 3 行）设置为红色。

**观察点**:
- 目标行所有瓦片应**立即变为红色**（< 100ms）
- **非目标行**的瓦片颜色应**完全不变**
- 右上角「脏行数」应显示 `1`
- 脏行列表应仅包含目标行索引

**量化标准**:
| 检查项 | 预期 | 容差 |
|--------|------|------|
| 更新响应延迟 | < 100ms | 肉眼不应感知延迟 |
| 非目标行不变性 | 颜色完全不变 | 0 个非目标瓦片颜色变化 |
| 脏行计数准确性 | dirtyRows.size = 1 | 精确匹配 |

**失败判定**: 若非目标行也发生颜色变化 → 脏行索引计算错误（BLOCKER）。若更新延迟 > 500ms → 提交性能退化（MAJOR）。

### 期望 3: Sheet 切换全局生效

**操作**: 选择不同活跃 Sheet（Sheet 0 默认 / Sheet 1 红色调 / Sheet 2 绿色调 / Sheet 3 蓝色调），点击「切换 Sheet」。

**观察点**:
- 所有瓦片颜色应**全局统一变色**（色调偏移）
- 地形类型分布（图案）保持不变，仅颜色方案变化
- 活跃 Sheet 槽位计数应更新（1/8 → 2/8 → 3/8 → 4/8）
- 切换应在 **500ms 内完成**所有 256+ 瓦片的颜色更新

**量化标准**:
| 检查项 | 预期 |
|--------|------|
| Sheet 切换耗时（256 瓦片） | < 500ms |
| 颜色变化一致性 | 所有瓦片同时变化，无逐个渐变 |
| 槽位计数 | 精确反映已使用的 Sheet 数 |

**失败判定**: 若切换后仅部分瓦片变色 → 粒子索引错误（MAJOR）。若切换耗时 > 2s → 性能退化（MAJOR）。

### 期望 4: 地图尺寸缩放兼容

**操作**: 切换地图尺寸为 8x8 → 16x16 → 32x32 → 64x64。

**量化标准**:
| 地图尺寸 | 瓦片数 | 最小 FPS | 期望 FPS |
|----------|--------|---------|----------|
| 8x8 | 64 | 58 | 60 |
| 16x16 | 256 | 55 | 60 |
| 32x32 | 1024 | 50 | 58 |
| 64x64 | 4096 | 30 | 55 |

**失败判定**: 若 64x64 时 FPS < 20 → 可扩展性不足（MAJOR）。

### 期望 5: 交互点击即时反馈

**操作**: 在地形网格上点击任意瓦片。

**观察点**:
- 被点击瓦片应**瞬间闪烁白色**（约 100ms），然后切换到下一地形类型颜色
- 悬浮提示框显示当前瓦片信息（坐标、地形类型、颜色值、Sheet 索引）
- 脏行计数器增加 1，脏行列表包含被点击瓦片所在行

**量化标准**:
| 检查项 | 预期 |
|--------|------|
| 点击响应延迟 | < 50ms |
| 闪烁持续时间 | 80-120ms |
| 悬浮提示更新延迟 | < 30ms |

## 检验流程

### 准备工作

1. 打开测试页面：`http://localhost:5173/test/terrain-sprite-layer/batch-rendering/`
2. 确认环境信息栏显示 WebGL 2.0
3. 默认状态：16x16 地图，棋盘格模式，256 瓦片，Sheet 0
4. 确认看到两种颜色（淡绿/棕褐）交替的棋盘格图案

### 步骤一：基础渲染性能验证

1. 观察 FPS 计数器稳定后数值（应在 55-60 范围）
2. 用鼠标滚轮缩放，观察瓦片网格：
   - 缩放时瓦片不应抖动
   - 瓦片间距均匀，无重叠
3. 按住鼠标左键拖拽平移视角
   - 瓦片应跟随移动，无残影

**预期**: 符合期望 1 → 继续

### 步骤二：脏行更新验证

1. 地形模式切换到「列渐变 (10 色)」→ 点击「应用地形模式」
   - 应看到从左到右 10 列不同颜色的垂直条纹
2. 将「更新行索引」滑块拖到 `3`（第 3 行，从上往下数）
3. 更新颜色选择「红色 (#e94560)」
4. 点击「更新整行」
5. 观察第 3 行（零基索引，即从上往下第 4 行）：
   - 该行所有瓦片应变为红色
6. 检查第 2 行（第 3 行）和第 4 行（第 5 行）：
   - 应保持列渐变颜色不变
7. 确认脏行数 = 1，脏行列表 = `3`

**预期**: 符合期望 2 → 继续

8. 更新行 `7` 为蓝色
9. 确认第 7 行变蓝，脏行数增加
10. 点击「提交脏行 (batch upload)」→ 脏行数应归零

### 步骤三：Sheet 槽位切换验证

1. 恢复棋盘格模式：「地形模式」→「棋盘格」→「应用地形模式」
2. 活跃 Sheet 选择「Sheet 1 (红-黑)」→ 点击「切换 Sheet」
3. 观察所有瓦片颜色应立即变为红色调
   - 原始淡绿 (#90EE90) 应变为约 (#A8FFA8×0.5 ≈ 偏红绿色)
   - 原始棕褐 (#8B4513) 应变为偏红棕色
4. 活跃 Sheet 槽位显示 `2 / 8`
5. 切换到「Sheet 2 (绿-黑)」→ 瓦片变绿调
6. 切换到「Sheet 3 (蓝-黑)」→ 瓦片变蓝调
7. 切回「Sheet 0 (默认)」→ 恢复原始棋盘格颜色

**预期**: 符合期望 3 → 继续

### 步骤四：地图尺寸缩放验证

1. 地图尺寸切换到「32x32 (1024 瓦片)」→ 点击「应用地形模式」
2. 观察：
   - 瓦片数量明显增多（10 倍）
   - 每个瓦片尺寸相应缩小
   - FPS 应在 50-60 范围
3. 地图尺寸切换到「64x64 (4096 瓦片)」→ 点击「应用地形模式」
4. 观察：
   - 瓦片非常密集
   - FPS 应在 30-60 范围
   - 滚轮缩放应仍然流畅
5. 恢复「16x16」

**预期**: 符合期望 4 → 继续

### 步骤五：交互点击验证

1. 在棋盘格上点击任意瓦片
2. 确认：
   - 瓦片短暂闪烁白色（约 100ms）
   - 然后变为下一地形类型颜色
   - 悬浮提示框显示坐标和颜色信息
3. 连续点击不同瓦片 5 次
4. 脏行数应反映所有被点击瓦片所在的行数

**预期**: 符合期望 5 → 继续

### 边界/异常测试

1. **更新边界行**：更新行 0 和行 15 → 应正确更新首行和末行
2. **快速连续更新**：连续 10 次点击「更新随机单元格」→ 无崩溃，帧率不下降低于 40
3. **地图尺寸 8x8**：切换到最小地图 → 瓦片应大而清晰，FPS = 60
4. **极端缩放**：滚轮缩小到最远 → 瓦片应可见（不消失）
5. **浏览器窗口调整**：缩小窗口到 800x600 → 测试页面正常显示

## 技术背景

### 本测试页面模拟的核心机制

| TerrainSpriteLayer 概念 | 本测试页模拟方式 |
|------------------------|-----------------|
| `vertices[4 * W * H]` | SPS `particles[]` (每个粒子 = 一个瓦片) |
| `dirtyRows: Set<number>` | `dirtyRows: Set<number>` (跟踪变更行) |
| `VertexBuffer.updateDirectly(data, offset)` | `sps.particles[p].color = ...` + `sps.setParticles()` |
| `sheets: (Sheet\|null)[]` (max 8) | `sheetSlotsUsed: Set<number>` (跟踪已使用槽位) |
| `_getOrAddSheetIndex()` | `activeSheetIndex` 选择器 + 槽位计数 |
| `Draw(viewport)` 脏行上传 | `commitDirtyRows()` 按钮触发 `sps.setParticles()` |

### TerrainSpriteLayer 顶点布局（参考）

```
vertexRowStride = 4 * mapSize.width     (每行 4 个顶点/方格 x 宽度)
vertices.length = vertexRowStride * mapSize.height

方格 (u, v) → 顶点偏移 = vertexRowStride * v + 4 * u
每方格 4 个顶点: TL (左上), TR (右上), BR (右下), BL (左下)

索引缓冲: INDICES_PER_CELL = 6 (三角形: 0-1-2, 2-3-0)
```
