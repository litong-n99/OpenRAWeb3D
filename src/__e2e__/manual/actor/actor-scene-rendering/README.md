## 测试目标

本测试页面验证 GameActor（Babylon.js TransformNode）在 3D 场景中的核心行为：
1. Actor 作为 TransformNode 正确定位于场景坐标系中
2. Trait 渲染 Mesh 正确挂载为 Actor 的子节点（父子层级关系）
3. Actor 生命周期管理：创建 → 旋转/缩放/移动 → 安全销毁
4. Owner 颜色系统：切换 Owner 时视觉颜色即时更新

---

## B. 期望结果（可量化验收标准）

### 期望 1: Actor 创建后立即出现在场景中

**操作**: 打开页面，观察默认 8 个 Actor。

**量化标准**:
- 页面加载后 **1 秒内** 应显示至少 8 个彩色方块（带白色边框和标签文字 A1-A8）
- 每个 Actor 方块大小在 **1.5-3.0 单位**（world units）之间
- Actor 位置随机分布在 **30x30 单位**的 XZ 网格区域内
- Actor 方块贴在地面上方（Y ≈ 0.05），无飘浮或穿透地面

**失败判定**: 页面空白超过 3 秒 → **BLOCKER** 渲染初始化失败

### 期望 2: Spawn/Move/Dispose 操作即时响应

**操作**: 依次点击 "Spawn 5" (3次) → "Move Random" → "Trash All"。

**量化标准**:
- 每次点击 "Spawn 5" 后 **200ms 内** 5 个新 Actor 出现在场景中
- "Move Random" 点击后 **100ms 内** 所有 Actor 跳到新的随机位置
- "Trash All" 点击后 **200ms 内** 所有 Actor 从场景中消失（包括子 Mesh）
- 活跃计数 `统计` 区域数字实时更新，与场景中可见 Actor 数量一致

**失败判定**: 操作后场景状态与统计数字不一致 → **MAJOR** 生命周期 bug

### 期望 3: 旋转动画连续无跳变

**操作**: 启用「动画旋转」复选框（默认已启用），观察 Actor 绕 Y 轴旋转。

**量化标准**:
- 所有 Actor 持续平滑旋转，**无可见步进**（旋转步进角 < 5 度每帧）
- 旋转速率约 **0.5 rad/s**（每帧约 0.008 rad）
- Actor 方块上的箭头指示器（白色三角）随旋转正确指向

**失败判定**: 旋转有明显跳变或卡顿 → **MINOR** 动画不流畅

### 期望 4: Cycle Scale 操作 Actor 大小连续变化

**操作**: 连续点击 "Cycle Scale" 按钮 4 次。

**量化标准**:
- 按钮标签依次显示: `Cycle Scale (0.5x)` → `(1x)` → `(2x)` → `(3x)` → 循环
- 所有 Actor 方块大小同步缩放，缩放倍数与按钮标签一致
- 缩放后 Actor 不飘浮或穿透地面（Y 位置保持不变）

**失败判定**: 缩放倍数与按钮标签不一致 → **MAJOR** TransformNode.scaling bug

### 期望 5: Toggle Owner 颜色切换正确

**操作**: 连续点击 "Toggle Owner" 按钮 3 次。

**量化标准**:
- 所有 Actor 颜色循环变化：原色 → 下一色 → 下一色 → 循环
- 三种 Owner 颜色:
  - Neutral: 灰色 (0.55, 0.55, 0.55) — 对应 ARGB `0xFF8C8C8C`
  - PlayerA: 蓝色 (0.20, 0.60, 0.95) — 对应 ARGB `0xFF3399F2`
  - PlayerB: 红色 (0.95, 0.33, 0.20) — 对应 ARGB `0xFFF25433`
- 颜色切换在 **100ms 内**完成（纹理替换）

**失败判定**: 切换后颜色与期望 ARGB 不匹配 → **MAJOR** 颜色系统 bug

### 期望 6: FPS 稳定性

**操作**: 创建 50+ 个 Actor（连续点击 "Spawn 5" 直至计数 > 50）。

**量化标准**:
- 50 个 Actor 同时渲染时 FPS 应维持在 **55-60**（现代 GPU）
- 70 个 Actor 时 FPS 应 >= **45**

**失败判定**: 50 个 Actor 时 FPS < 30 → **MAJOR** 渲染性能问题

## 检验流程

### 准备工作

1. 打开测试页面：`http://localhost:5173/test/actor/actor-scene-rendering/`
2. 确认环境信息栏显示 WebGL 2.0
3. 确认 FPS 显示在 50-60 范围
4. 确认场景中有 30x30 网格参考线

### 步骤一：基础渲染检查

1. 等待页面完全加载
2. 观察场景中的 Actor 方块
3. 放大 (scroll up) 观察个别方块的纹理细节
4. 确认能看到白色箭头（朝向指示器）

**预期**: ✅ 符合期望 1

### 步骤二：生命周期操作

1. 点击 "Spawn 5" 三次 → 统计应显示 "活跃 Actor: 23 总创建: 23"
2. 点击 "Move Random" → 所有方块移向新位置
3. 点击 "Trash All" → 统计应显示 "活跃 Actor: 0 总创建: 23"

**预期**: ✅ 符合期望 2

### 步骤三：动画与交互

1. 观察 Actor 旋转约 5 秒 → 旋转平滑
2. 取消「动画旋转」→ 旋转停止
3. 重新启用「动画旋转」→ 旋转恢复

**预期**: ✅ 符合期望 3

### 步骤四：缩放与颜色

1. 点击 "Cycle Scale" 四次 → 验证按钮标签与方块大小一致
2. 点击 "Toggle Owner" 三次 → 验证颜色循环正确
3. 放大观察颜色细节

**预期**: ✅ 符合期望 4, 5

### 步骤五：性能测试

1. 连续点击 "Spawn 5" 直至活跃 Actor >= 50
2. 记录 FPS
3. 点击 "Move Random" → 验证无卡顿
4. 点击 "Trash All" → 验证 FPS 恢复

**预期**: ✅ 符合期望 6

### 边界/异常测试

1. **快速连续操作**：快速点击 Spawn + Move + Scale 各 5 次 → 无崩溃
2. **Trash 后重新 Spawn**：销毁所有后再创建 5 个 → 正常显示
3. **Z-fighting**：缩放摄像机到最近距离 → Actor 方块无 Z-fighting
4. **摄像机拖拽**：平移摄像机到边缘 → Actor 不被截断
