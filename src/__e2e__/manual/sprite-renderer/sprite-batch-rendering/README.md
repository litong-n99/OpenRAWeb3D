# SpriteRenderer - ThinInstances 批量渲染性能验证

> **人工验收测试页**
> 模块: SpriteRenderer (ThinInstancesGroup.setInstances)
> 测试ID: `sprite-renderer/sprite-batch-rendering`
> OpenRA 对照: `SpriteRenderer.ts` ThinInstancesGroup.setInstances()
> 创建日期: 2026-06-06
> 最后修复: 2026-06-08（修复精灵不可见 bug — 根因见下文）

---

## 测试目标

本测试页面验证 SpriteRenderer 中 ThinInstances 批量渲染的性能表现。OpenRA 原始代码中使用手动顶点缓冲 + DrawQuadBatch 渲染精灵；迁移版使用 Babylon.js 的 ThinInstances（单个 Mesh + 批量矩阵缓冲）替代。此测试验证在不同精灵数量下（100/500/1000/5000）ThinInstances 的性能是否满足 RTS 游戏需求。

---

## B. 期望结果（可量化验收标准）

### 期望 1: 500 个精灵 — FPS 稳定在 55-60

**操作**: 默认状态（500 精灵），观察 FPS 计数器和实时图表。

**量化标准**:
| 精灵数量 | 最低 FPS | 平均 FPS | 帧时间 |
|---------|----------|----------|--------|
| 100 | >= 58 | >= 59 | <= 17ms |
| 500 | >= 55 | >= 57 | <= 18ms |
| 1000 | >= 50 | >= 55 | <= 20ms |
| 5000 | >= 20 | >= 25 | <= 50ms |

**失败判定**: 500 个精灵时 FPS 持续低于 30 -> **MAJOR** 性能退化

### 期望 2: 精灵数量切换时无卡顿

**操作**: 依次点击预设按钮 100 -> 500 -> 1000 -> 5000，观察过渡过程。

**量化标准**:
- 数量切换在 **200ms 内** 完成视觉更新
- 切换期间 FPS 不降至 0（不冻结）
- 新精灵立即出现在随机位置（无逐步出现动画）

**失败判定**: 切换时页面冻结 > 500ms -> **MAJOR** 主线程阻塞

### 期望 3: 精灵旋转动画流畅无闪烁

**操作**: 确保「精灵动画」已勾选，观察精灵绕 Y 轴旋转。

**量化标准**:
- 精灵旋转平滑，无可见步进（旋转步进角 < 3 度每帧）
- 无精灵跳变或闪烁
- 颜色维持稳定（无闪烁变色）
- 旋转动画持续进行，所有精灵同时旋转

### 期望 4: 压力模式下的稳定性

**操作**: 勾选「压力模式（每帧重新创建精灵）」，运行 10 秒。

**量化标准**:
- FPS 不低于正常模式的 50%
- 无内存泄漏迹象（连续运行 30 秒后 FPS 不持续下降）

### 期望 5: 视觉正确性

**操作**: 放大观察个别精灵。

**量化标准**:
- 精灵为水平放置的彩色圆形纹理（地面平铺，从俯视 RTS 视角可见）
- 精灵位置随机分布在 40x40 区域内（XZ 平面），无重叠异常
- 8 种颜色（红/绿/蓝/黄/紫/青/橙/白）的精灵均匀分布
- 精灵缩放范围 2-5，大小不一自然（在 40x40 区域内从俯视 RTS 视角清晰可见）
- 精灵纹理为白色圆圈 + 半透明白色外环，通过 instanceColor 着色

## 已知问题 & 修复记录

### 2026-06-08 (2): GC 压力导致 FPS=2（已修复）

**根因**: `applyThinInstances()` 在动画模式（默认勾选）下每帧调用，内部对每个精灵创建 5 个 Matrix 对象（`Matrix.Scaling` + `Matrix.RotationY` + `Matrix.Translation` + 2 次 `multiply`），加上两个大 `Float32Array`。500 精灵时每帧分配 ~2500 Matrix + 2 数组，触发巨量 GC，FPS 降至 2。

**修复**:
1. 预分配 `matricesBuffer` / `colorsBuffer`，仅在 `spriteCount` 变化时重新分配
2. 使用 `Matrix.ComposeToRef` + `Quaternion.RotationYawPitchRollToRef`（ToRef 变体）替代逐 Matrix 构建，复用 4 个预分配对象（`_scale` / `_translation` / `_rotation` / `_world`）
3. 每帧写入成本降至纯数值填充（~32KB 写入 + 零 GC）

**同时修复**: sprite scale 从 0.3-0.8 增大到 2-5 单位，确保在 camera radius=45 下肉眼清晰可见。

### 2026-06-08: 精灵不渲染问题（已修复）

**根因**: `MeshBuilder.CreatePlane` 创建垂直平面（XY 平面，法线 +Z）。ArcRotateCamera 在 alpha=-PI/2, beta=PI/3 时相机位置为 (-26, 15, 0)，Z 分量为 0。相机视线与平面法线垂直（点积 = 0），导致所有精灵边缘朝向摄像机，完全不可见。

此外，`billboardMode = BILLBOARDMODE_Y` 对 ThinInstances 无效 — Babylon.js 的 ThinInstances 使用独立的世界矩阵，不继承基础 Mesh 的 billboard 旋转。

**修复**:
1. 将基础 Mesh 从 `CreatePlane`（XY 垂直平面）改为 `CreateGround`（XZ 水平平面），使精灵平贴在地面上，从 RTS 俯视视角清晰可见
2. 旋转轴从 Z 改为 Y（`RotationY`），模拟地面单位的朝向旋转
3. 精灵分布从 XY 平面改为 XZ 平面，Y 轴仅保留微小高度偏移（0.05-0.25）
4. 摄像机 alpha 从 -PI/2 改为 -PI/4，使相机同时具有 X 和 Z 分量
5. 摄像机 beta 从 PI/3 改为 PI/4（更俯视）
6. `thinInstanceSetBuffer` 设置 `staticBuffer=false`，支持动态矩阵更新
7. 使用 `thinInstanceRefreshBoundingInfo` 代替 `refreshBoundingInfo`，正确计算包含所有 ThinInstances 的包围盒
8. 渲染循环中添加 try-catch，防止运行时异常导致循环静默中断

## 检验流程

### 准备工作

1. 打开测试页面：`http://localhost:5173/test/sprite-renderer/sprite-batch-rendering/`
2. 确认环境信息栏显示 WebGL 2.0
3. 关闭其他 GPU 密集型应用（浏览器其他标签页、视频播放等）
4. 确认屏幕刷新率（60Hz/120Hz/144Hz）
5. 确认页面加载后立即看到数百个彩色圆形精灵分布在 3D 场景中

### 步骤一：100 个精灵基准测试

1. 点击「100」预设按钮
2. 等待 3 秒让 FPS 稳定
3. 记录 FPS 计数器和帧时间
4. 滚动鼠标滚轮放大观察精灵 -> 确认精灵正确渲染（彩色圆形，水平平铺在地面上）

**预期**: 符合期望 1 中 100 精灵的标准 -> 继续

### 步骤二：500 个精灵验收

1. 点击「500」预设按钮
2. 观察 FPS 图表 5 秒
3. 确认平均 FPS >= 57，最低 FPS >= 55
4. 观察精灵是否平稳旋转

**预期**: 符合期望 1 中 500 精灵的标准 -> 继续

### 步骤三：1000 个精灵验收

1. 点击「1000」预设按钮
2. 观察 FPS 图表
3. 确认平均 FPS >= 55
4. 用鼠标拖拽平移摄像机 -> 确认无卡顿

**预期**: 符合期望 1 中 1000 精灵的标准 -> 继续

### 步骤四：5000 个精灵压力测试

1. 点击「5000」预设按钮
2. 观察 FPS（预期降低但仍可使用）
3. 确认最低 FPS >= 20

**预期**: 符合期望 1 中 5000 精灵的标准

### 步骤五：动态切换测试

1. 依次点击：100 -> 1000 -> 5000 -> 100
2. 每次切换观察是否有冻结（期望 2）

### 步骤六：压力模式测试

1. 设置精灵数量为 500
2. 勾选「压力模式」
3. 运行 10 秒
4. 取消勾选
5. FPS 应恢复到之前水平（无内存泄漏）

### 边界/异常测试

1. **快速连续切换**：点击 100 -> 500 -> 1000 -> 5000 各 5 次 -> 无崩溃
2. **取消动画**：取消「精灵动画」-> FPS 应略微提升
3. **窗口缩放**：缩小到 800x600 -> FPS 应持平或略升
4. **摄像机拖拽**：用鼠标拖拽旋转/平移摄像机 -> 精灵始终可见，无消失现象
5. **极端缩放**：滚轮缩放到最近（radius=5）和最远（radius=100）-> 精灵渲染正常
