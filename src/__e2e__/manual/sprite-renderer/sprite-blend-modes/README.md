# SpriteRenderer - 混合模式验证

> **人工验收测试页**
> 模块: SpriteRenderer (blendModeToAlphaMode)
> 测试ID: `sprite-renderer/sprite-blend-modes`
> OpenRA 对照: `SpriteRenderer.ts` BlendMode 枚举 + `blendModeToAlphaMode()`
> 创建日期: 2026-06-06

---

## 测试目标

本测试页面验证 10 种 OpenRA BlendMode 到 Babylon.js alphaMode 的映射正确性。`blendModeToAlphaMode()` 函数将 OpenRA 语义的混合模式映射到 Babylon.js 引擎的 6 种 GPU 混合状态。在 OpenRA 原始代码中，混合模式直接影响 `GL.BlendFunc()` 的参数组合；在 Babylon.js 中通过 `material.alphaMode` 控制。每个模式必须有对应的视觉特征。

---

## B. 期望结果（可量化验收标准）

### 期望 1: Alpha 混合模式 — 标准半透明效果

**操作**: 选择「Alpha」或「Translucent」混合模式，观察红-青双圆叠加面板。

**观察点**:
- 两个半透明径向渐变圆（红+青）重叠区域呈现自然的颜色混合
- 重叠区域颜色为红色和青色的加权混合（红+青 → 灰白或紫红，取决于 Alpha 值）
- 无硬边缘或颜色突变

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| 透明效果 | 棋盘格背景通过半透明区域可见 |
| 叠加区域 | 颜色平滑混合，无突变 |
| Alpha/Translucent 一致性 | 两种模式视觉效果完全一致 |

### 期望 2: Additive 加法混合 — 明显变亮

**操作**: 选择「Additive」或「LowAdditive」模式。

**观察点**:
- 重叠区域**明显变亮**
- 红+青重叠区域呈现近乎白色（白色 = #FFFFFF 附近）
- 不会出现深色/黑色区域
- LowAdditive 的亮度增量比 Additive 小（相同 alpha 下颜色更暗）

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| 重叠区域亮度 | 明显高于单独红色或青色区域 |
| 无暗区 | 任何叠加区域不应暗于原始颜色 |
| 极限叠加 | 两个 α=0.95 圆重叠处接近白色 (#FEFEFE) |

### 期望 3: Subtractive 减法混合 — 明显变暗

**操作**: 选择「Subtractive」模式。

**观察点**:
- 重叠区域**明显变暗**，趋向黑色
- 红+青重叠区域呈现暗色/黑色
- 单独圆区域不受影响

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| 重叠区域亮度 | 低于单独红色或青色区域 |
| 暗化程度 | 肉眼可见明显变暗（至少 30% 亮度降低） |

### 期望 4: Multiply 乘法混合 — 颜色暗化

**操作**: 选择「Multiply」、「Multiplicative」或「DoubleMultiplicative」模式。

**观察点**:
- 重叠区域变暗，保留底色色相
- 红色+青色在 Multiply 下呈现非常暗的颜色（两种颜色通道相乘后接近黑色）
- 与 Subtractive 的区别：Multiply 更均匀地降低亮度

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| Multiply 与 Subtract 差异 | 肉眼可辨，Multiply 暗化更均匀 |
| Multiplicative 与 Multiply 一致性 | 视觉效果完全一致 |

### 期望 5: Screen 屏幕混合 — 柔和变亮

**操作**: 选择「Screen」模式。

**观察点**:
- 重叠区域变亮但不过曝
- 与 Additive 的区别：Screen 变亮更柔和，不会产生纯白色区域
- 图像整体保持柔和质感

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| Screen 与 Additive 差异 | Screen 更柔和，Additive 更亮 |
| 无过曝 | 不应出现大面积纯白 |

### 期望 6: None 模式 — 完全不透明

**操作**: 选择「None」模式。

**观察点**:
- 圆形完全不透明，Alpha 通道被忽略
- 半透明渐变区域全部变为不透明
- 无棋盘格背景穿透

**量化标准**:
| 检查项 | 预期行为 |
|--------|---------|
| 透明度 | 完全无透明效果 |
| Alpha 忽略 | 即使纹理有 alpha 渐变，渲染为不透明 |

### 期望 7: 模式切换即时性

**操作**: 在混合模式列表中快速连续点击不同模式。

**量化标准**:
- 每个模式切换后 **50ms 内** 视觉更新完成
- 切换无闪烁或残影

## 检验流程

### 准备工作

1. 打开测试页面：`http://localhost:5173/test/sprite-renderer/sprite-blend-modes/`
2. 确认底部环境信息栏显示 WebGL 2.0
3. 确认看到 10 个面板（5x2 网格），每个包含两个重叠的半透明圆（红色+青色）

### 步骤一：逐个验证混合模式

1. 从混合模式列表点击「None」
   - 确认：选中面板中圆形完全不透明，无透明效果
2. 点击「Alpha」
   - 确认：圆形半透明，棋盘格背景可见，重叠区域颜色混合自然
3. 点击「Additive」
   - 确认：重叠区域明显变亮（期望 2）
4. 点击「Subtractive」
   - 确认：重叠区域明显变暗（期望 3）
5. 点击「Multiply」
   - 确认：重叠区域变暗且均匀（期望 4）
6. 点击「Screen」
   - 确认：重叠区域柔和变亮（期望 5）
7. 点击「Translucent」
   - 确认：与 Alpha 完全相同（期望 1）
8. 点击「Multiplicative」
   - 确认：与 Multiply 完全相同（期望 4）
9. 点击「DoubleMultiplicative」
   - 确认：与 Multiply 相同或稍暗（期望 4）
10. 点击「LowAdditive」
    - 确认：比 Additive 更暗的加法效果（期望 2）

**预期**: 所有模式视觉特征明显区分 → 继续

### 步骤二：全局透明度调节

1. 拖动「全局透明度」滑块从 1.00 到 0.00
2. 观察所有面板的透明度是否同步变化
3. 恢复到 1.00

### 步骤三：快速对比模式

1. 勾选「快速对比模式」
2. 观察面板是否每 1.5 秒自动切换高亮的混合模式
3. 取消勾选停止

### 步骤四：显示选项验证

1. 取消勾选「显示棋盘格背景」→ 背景变为纯色
2. 重新勾选 → 棋盘格恢复
3. 取消勾选「显示混合模式标签」→ 标签消失
4. 取消勾选「全部显示」→ 仅显示选中模式的面板

### 边界/异常测试

1. **透明度极限**：全局透明度设为 0 → 所有面板应完全不可见
2. **透明度极限**：全局透明度设为 0.5 → 所有面板半透明
3. **窗口缩放**：缩小窗口到 800x600 → 所有面板正常显示
